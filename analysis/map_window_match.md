# 实机截图 ↔ 图集窗口对照定案 (2026-09-18)

素材: `analysis/realmap.png` (用户实机截图 1510×1127, 内容区 (2,1)-(1510,1125) → 缩到原生 1024×768)
对象: MAP01.MAP 48 页图集 (`prototype/assets/map01_atlas.png`) / MAP01.BIN 三层

## 引擎渲染管线 (代码级定案, 2026-09-18 反编译逆向)

加载链 (MapCtrl.cpp, yoshida):
- `43a640`: BIN 整文件 → MapCw (缓冲=文件原样; W=+4/H=+6 即 u16 头 [4]/[6])
- `43a920`: MAP 整文件 → gmp; `4167e0→41f090→41f0e0` (DxTexTbl.cpp):
  DX 表 @gmp+0x404 = `{u32 表长; u32 count; u32 offs[count]; 条目×count}`,
  每条目 = `"DX\2\0" + u16×4 (256,256,256,256) + 0x20000B X1R5G5B5 像素`
  → count 张 D3D8 纹理存入 slot 0x5c (this+0x263b4)。
  MAP01 实测: count=48, offs 步长 0x2000C ✓ (旧"53×(u16,u16) 步长表"悬案=此偏移表, 结案)
- `41f340`: 逐条目建纹理; 条目可 "BM"(BMP)/"DX"/"Dm-No-MakeTex"(跳过)

绘制 (每帧, 视口 33×37 格):
- **主地面 `43e540`**: 单张大纹理 (this+0xdc, 尺寸 this+0xec/0xee) — 逐格
  32×16 TRIANGLEFAN quad, UV = (cell_x×32/宽, cell_y×16/高) **全图线性 = 图集恒等**;
  FVF 0x1C4 (XYZRHW|SPECULAR|TEX1, **无 DIFFUSE** — 顶点里写的灰度 dword 落在
  SPECULAR 槽且 SPECULARENABLE 关闭, BIN 第 6 字节不参与颜色)。**composed=atlas 定案**。
- **页覆盖层 `43eba0`**: 按页取样 (tex_index = cx/8 + pageX×(cy/16) — 行优先代码铁证),
  条件 = BIN 每格第 6 字节(o_hi)≠0 才画; MAP01 全 0 → 恒不画 (功能: 其他地图的贴片覆盖)
- **阴影层 `43fd80`**: 两个 W×H 单字节数组 (43cfe0 分配+43d0c0 清零, **运行时动态计算**),
  灰度 = A[cell] (或 B/3), 顶点 y −偏移, 按页取样同款 quad — 实机画面石影来源
- **占据标记 `43c470`**: MapCm->data[cell] 高字节 ±1 (单位进/出格);
  `43c0c0` 占据查询 (OOB 返回 10)。**MapCm->data 是纯运行时状态, BIN 三层不进它**
- **相机 `43b460`**: scroll 钳制 [0, W×32−0x400]×[0, H×16−0x238] → **视口 = 1024×568**
  (底部 200px 为 UI 区; 实机截图地图内容止于 y≈568 ✓)

关键纠正 (vs 实机截图对照前的认识):
1. BIN 三层**不是贴图选择器** — 地面=大纹理恒等; MapCm 是运行时状态
2. 页序行优先由 `43eba0` 的 tex_index 公式直接确证 (不再只是 BMP 相关推断)
3. 阴影不是文件数据 — 动态计算 (重制版需自己实现阴影算法, 或从 VPT/高度数据推)

## 方法

1. 图集页心 64×64 patch 对屏幕全搜 NCC (float64 + scipy fftconvolve;
   早期 float32 积分图版本精度崩坏, 分数>1000, 已弃)
2. 屏幕网格 56×56 patch (步 64) 全图集搜 → 粗偏移场
3. 中带 (y 380..444) 16px 步进细扫 → 缝位置与偏移
4. 48×48 patch (步 48) 局部搜索 → NCC 热图 + dx/dy 偏移场 (`_ncc_heat.npy`/`_offxy.npy`)

## 定案结论

### 1. 世界 = 图集的平移窗口 (94% 像素级吻合)

- **dy 恒 434±2, 全高无跳变** (屏幕 y 0..480 匹配区连续跨图集页行边界 512/768/1024)
- **dx 分竖直带**: 带内恒定, 带间跳 ±43~48px; 除跳变外呈 ~1.02 缩放漂移
  (+421@x96 → +438@x848, 漂移来自截图裁边估计误差, 非引擎缩放)
- 屏幕窗口 ≈ 图集 [520,500]-[1400,1100] 区域 (页行 1..4 × 页列 2..5)
- 屏幕格贴片 (2×2 格块) 独立匹配: 同 t 值相邻格的图集位置保持世界相对位移
  (如格(19,36)/(19,38) → 图集 (556,578)/(556,610), Δ=32px=2 格) ✓

**即: 已验证窗口内 世界像素 = 图集像素 (平移), "composed=atlas 恒等"对该窗口成立。**

### 2. 两条 48px 缝带 (世界≠图集平铺的例外)

- 缝带 1: 屏幕 x≈144..192 (图集 x≈592 附近), dx 跳 421→373 (-48)
- 缝带 2: 屏幕 x≈432..480 (图集 x≈870 附近), dx 跳 384→427 (+43)
- 缝带 = 热图失配竖条, 宽恰 = 跳变量; **缝不在 256 页边界上** (在页内)
- 推论: 世界由"大块图集平移拷贝 + 少数缝带另行取样"拼成;
  页边界的"断裂"(列差/基线 2~6×, 全线)很多是**真实世界的缝带/素材页交界**,
  不是页序错误 → 行优先排列仍最优 (对 BMP corr: 行优先 0.488 vs 列优先/翻转/转置 ≤0.354)

### 3. BIN 格式修正 (map_export v1.1)

- 旧解读 "16B 头 + 3 个 W×H 平面" 是**误读**: 平面切法重排后产生
  `x+64y ≡ 0 (mod 3)` 的伪条带 (terrain"每 3 行相位循环"), 与旧"object 每 3 行横条"伪像同源
- 正确: **头 8×u16 [2048,1536,64,96,256,256,8,6] + 每格 3×u16 cell-major 交错 (t,v,o)**
- 修正后 MAP01: terrain 全格有值 {1..5,9..13,17} (11 占 37%),
  variant 仅 35 格非零, object 全 0 → **MAP01 的 variant/object 语义上近空**
- 层值 t 不是"贴片 ID": 同 t=11 的格在图集分散多处 (世界各处取样)

### 4. 附带观察

- .MAP 页间 12B 定长标记 `44 58 02 00 | 00 01 ×4` ("DX"+2+256×4, 疑 D3D 纹理块头),
  全 48 页相同, 不含页序; 末页后另有 832B 尾巴 (未解, 开口)
- 小地图黑区 = 战争迷雾 (开局 40s), 非岛屿形状 (terrain 全格有值佐证)
- 屏幕中带两处 NCC 跌落 (sx 208..304 / 736..784) = 水晶塔与单位精灵遮挡, 非图集问题
