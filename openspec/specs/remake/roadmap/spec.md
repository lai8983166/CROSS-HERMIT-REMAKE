# 超魔法大战（Cross Hermit）重制路线图

## Purpose

本规格规定 Cross Hermit 复刻工作的总范围、验收方式和里程碑顺序，作为后续各个 change 的共同依据。它取代原来的逆向总规格（`openspec/specs/reverse-engineering/completion/spec.md`，2026-11 起转为参考）。

交付物是**可玩的 Godot 重制版**。逆向工程不再是目的本身，而是手段：只在重制被具体问题卡住、无法从黑盒观察或既有资料得出正确行为时，才针对该阻塞点进行逆向。

列出目标不表示已经实现。日期不写入里程碑；进度以实际证据（可运行的重制、回归测试、README 与 git log）为准。

## 验收方式：行为对等

重制的验收标准是**行为对等**，不再以逐指令或逐 API 重放作为验收。

- **定义**：在**同一存档、同一操作序列**下，重制版的可观察结果与原版一致。可观察结果包括：
  - 数值（属性、伤害、成长、金钱、经验等）；
  - 剧情分支与事件旗标；
  - 战斗战果（胜败、存活、掉落、奖励）；
  - 角色成长与转职结果；
  - 画面文字（对话、菜单、胜利/失败提示）。
- **不要求**：重制内部实现与原版的指令序列、函数调用、内存布局或 API 调用顺序一致。重制可以用任何实现方式，只要外部可观察结果对等。
- **证据形式**：每个功能里程碑以回归测试或可复核的对照记录证明对等；对照用的原版观察结果须注明来源。

## 逆向工作规则

逆向在重制驱动模式下是受约束的辅助活动：

- 每个逆向 change **必须在开头写明它对应的重制阻塞点**：重制的哪个功能、因为什么问题无法仅凭黑盒观察或既有资料完成。
- 逆向的产出必须**落成可被重制直接使用的成果**：数据（提取出的表、资源）、公式（经验证的规则），或回归测试（锁定对等行为）。不以“解释了原版如何做”本身作为交付。
- 继续遵守 AGENTS.md 的证据体积规则：**每个 change 新增持久化证据不超过 256 MiB**，大型来源按既有惯例本地与仓库外逐字节备份，Git 只收复现代码、小报告与大小/SHA/位置清单。
- 逆向不改原存档、原始资产字节与已有的 Godot 代码所有权规则；已验证结论作为参考保留。

## 里程碑（只排顺序，不写日期）

里程碑按依赖顺序排列，前一个是后一个的前提。每个里程碑完成的判据是对应范围内达到行为对等并有回归证据。

### M1：显示与文字
- Godot 窗口可交互：能加载存档、接收输入、推进既有学校试玩流程。
- 文字编码：Big5 文本在**提取阶段**转为 UTF-8，不经过运行时的 ACP936 代码页转换（原版乱码的根因）。
- 对话与胜利/失败文字在重制中可读、内容与原版一致。

### M2：学年循环（10 月至 3 月）
- 学年循环从 10 月推进到 3 月，每周可推进。
- 包括排课、每周结算、转职资格刷新等养成系统，数值与分支与原版对等。

### M3：战斗
- 45 张战斗地图在重制中实时战术可玩。
- 战果与角色成长与原版对等（同存档同操作下结果一致）。

### M4：剧情
- YBC32 脚本解释器在重制中跑通全部 **153 份章节脚本**。
- 剧情分支与事件旗标与原版一致。

### M5：结局与周目
- 多结局可达并正确。
- 存档读写、周目继承（能力减半、旗标清零等规则）与原版对等。

### M6：收尾
- BGM、语音、过场影片（FMV）接入。
- mod 加载器（change `add-mod-loader`）。

## Requirements

### Requirement: 交付物是可玩的 Godot 重制版
重制工作 SHALL 以可玩的 Godot 重制版为交付物；逆向仅在重制被具体问题卡住时按需进行，且每次逆向须对应一个明确的重制阻塞点。

#### Scenario: 逆向以重制阻塞点为前提
- **WHEN** 创建或接续一个逆向 change
- **THEN** 该 change 开头写明对应的重制阻塞点（哪个功能、因何无法仅凭黑盒观察或既有资料完成）
- **AND** 其产出落成数据、公式或回归测试，供重制直接使用，而非仅解释原版实现

### Requirement: 验收以行为对等为准
重制的里程碑 SHALL 以行为对等验收：同一存档、同一操作序列下，可观察结果（数值、剧情分支、战果、成长、画面文字）与原版一致；不再以逐指令或逐 API 重放作为验收标准。

#### Scenario: 功能里程碑达到对等
- **WHEN** 核对某个功能里程碑（M1–M6）
- **THEN** 以回归测试或可复核对照记录证明，同存档同操作下重制的可观察结果与原版一致
- **AND** 对照用的原版观察结果注明来源；重制内部实现与原版指令/调用顺序不要求一致

### Requirement: 证据体积与完整性
重制与逆向工作 SHALL 遵守 AGENTS.md 的证据体积与完整性规则。

#### Scenario: 每个 change 的证据受限
- **WHEN** 一个 change 产生新的持久化证据
- **THEN** 新增证据默认不超过 256 MiB，大型来源本地与仓库外逐字节备份，Git 只收复现代码、小报告与大小/SHA/位置清单
- **AND** 原存档、原始资产、私有检查点与已有 Godot 代码保持原字节，不删除任何证据或数据

### Requirement: 里程碑按顺序推进
里程碑 SHALL 按 M0→M6 的依赖顺序推进，不写入日期；进度以实际证据为准。

#### Scenario: 进度核对不以预测充当完成
- **WHEN** 核对里程碑进度
- **THEN** 以可运行的重制、回归测试、README 与 git log 为依据判断某里程碑是否达成
- **AND** 不把未验证的计划或旧预测当作已完成
