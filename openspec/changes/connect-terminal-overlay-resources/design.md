# Design

## Context

见proposal。以已验TaskMachine的新战斗实例及自然原任务栈为起点，保持前驱不变；407870经owner+844h查询84字节IMAGE记录，之后从owner取绘制设备并进入覆盖层原入队代码。

## Goals / Non-Goals

**Goals:** 实际源资源初始化、完整查询和原VM前进；当前资源/平台边界的拥有关系可核查。

**Non-Goals:** 不以历史COM回执宣称新GPU，不将入队称实际显示，不把下一有来源的依赖停点称完整终局。

## Decisions

- 追溯原加载代码绑定的组20文件，独立解析容器及纹理像素，再复用已验真实文件/CRT/纹理桥接能力；只在明确平台边界翻译当前地址和句柄。
- 新资源建立在前向原任务之前，保留原根调用及清理声明；同实例自然续接407870，不重新造PC/wait或派生资源记录。
- 代码/IAT及只读拥有区受守卫约束；全部映射、完整57项CPU、原指令/写入摘要和原栈新实例重放，并独立预测关键查询结果和VM变更。
- 真实GPU可用性与输入桌面分别检查；需要解锁时提前说明。清理资源和原前向进度分别记录。

## Risks / Trade-offs

- [加载器/队列出现新增真实依赖] → 保留诊断和明确调用边界，沿来源补齐，不用返回桩跳过。
- [原生指针在重放变化] → 平台边界使用有角色类型的地址投影，全资源读回/正常清理另核对。
- [初始方法输入被误称原完整启动] → 逐项列出初态和独立初始化根，整体R3/R4/R5/R6保持未完成。
