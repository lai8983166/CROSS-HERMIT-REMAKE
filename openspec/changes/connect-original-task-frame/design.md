# Design

## Context

R2保留场景的454CF0原任务返回后，输入+630h为FF。425ED0在再次登记请求前检查该字节必须为0；425DE0才是原帧入口消化请求的函数。原49E540先调用425DE0和队列复位，再由4217C0调度任务。源49E540还含真实线程/事件调度，本次完整任务单元不冒充其已接通。

## Goals / Non-Goals

Goals：把R2的67次有界VM根替换为完整任务更新，真实查询输入法状态，保留实际文字/设备寿命，核对任务前后原栈/CPU/输入请求和源调用链。Non-goals：物理键鼠捕获、完整OS消息/线程调度、静态图片恢复或R3整体验收。

## Decisions

- 继续使用R2原初始化+明确逻辑重建，复用原生渲染桥v4，原存档/旧检查点/历史报告不改；新报告与复核工具单独命名。
- 仅在原IAT实际目标处调用真实IMM32.ImmGetOpenStatus，当前输入上下文为0。拒绝非零未拥有上下文；记录实际系统返回、平台位数与模块身份，不把旧声明0当作观察值。
- 源425DE0、425E60、425C70、425ED0及454CF0全部执行原机器码，绝不手动清+630h，也不绕过断言。输入重置与完整任务是明确驱动根，分别记录；不把它们标为49E540自然外层调用。
- 独立验证复用R2Replay，增加真实系统API返回回放；逐段校验源输入、全部原指令/写入及完整任务边界，复用实际图像像素核对。

## Risks / Trade-offs

- 待处理IME请求被误判为未初始化索引 → 原字节/分支/调用顺序证据明确纠正，只改当前总规格说明，不重写历史报告。
- 完整任务可能暴露世界/音频依赖 → 在原边界记录并解决本功能路径需要的来源依赖，不能以VM短路替代完整任务。
- 新调用根混同完整主循环 → 报告同时记录完整任务已执行和原外层未执行，R3保持进行中。
