# Design

## 当前开发顺序（2026-11-14 用户确认）

静态明确的逻辑先还原并进入Godot，动态验证只针对会改变当前功能正确性的未知点。
完整当前所有权、连续执行、两例新寿命及独立重放仍是最终验收要求，不是所有重制
开发的共同前置。以下A/B/C及原八项任务保持验收含义，不因逻辑模块通过而勾选。
当前实现包括453CB0至453CDD的显式恢复状态机、场景5后继请求预测，以及学校可玩
战斗试验的结束/消费/结果页/返回准备流程。后者采用明确的本地初始队伍结束规则，
不使用原场景5投影，不推进正式冒险、奖励或存档；完成值不等于胜负selector，
4967B0不等于奖励，三次等待不等于三个渲染帧或完整外层清理。
具体未知、最小核验及可实现范围见 docs/terminal_logic_reconstruction.md。
STOPPED_SCOPE_GUARD仍有效；不以本次开发自动恢复冷启动执行器整合或宿主运行。

## Context

父功能验收为 `terminal-unit-frontends-acceptance-v1-20261106.json`；性能适配及复用验证的验收为 `reverse-validation-acceptance-v1-20261106.json`。当前前缀显式调用 `4539B0`，没有真实 `451670` / CRT worker 祖先帧。旧原生助手已结束，旧句柄不能恢复为当前所有者。

## Goals / Non-Goals

目标是由原指令推进等待、结果消费和真实退出链，并在真实依赖阻塞时提供精确的状态和可复用接续。单一等待返回、独立注册实验、单纯事件发布不构成完整战斗退出。奖励、学校全流程以及全部主线完成不因本有限单元自动成立。

## Decisions

1. 先核对原字节和两个当前来源的实际 TASK/MAIN/栈状态，运行有界尾段。未建立合法事件所有权前停在真实平台边界，不调用无效 Win32 句柄；不因原函数忽略 WAIT_FAILED 而误报成功。
2. 区分原逻辑调度证据、当前原生叶操作和原 CRT 线程寿命。需要新增注册或线程来源时，使用原构造、注册、包装器及当前所有者；不将 renderer manager 当成 scheduler，不手写线程/TLS/完成字段。
3. 新增实现，不改冻结前缀。每次实际覆盖的新代码范围、平台 ABI、完整 CPU/内存/权限、原始指令和写轨迹、资源正常清理必须能独立复核。已有 REP 例外仅限原冻结规则，不扩大。
4. 先完成代表例有界路径和验证器，再安排耗时的新鲜执行/独立重放；共同契约修改覆盖第二例。只允许来源、实现、输入、验收器身份一致的显式验证接续，失败不自动重采。
5. 证据引用固定父摘要，保存增量及必要原字节。新增持久化目标 256 MiB 以内；不重复保存父历史/内存页/纹理。仅当前成功来源和必要小失败差异长期保留。
6. 剩余工作按 tasks 中 A/B/C 三关口执行。A 要从合法当前所有者连续通过原等待、
   结果消费及外层返回；B 要证明同一链上的真实资源/PTD 释放与后继消费；C 保持两例
   新鲜原生寿命、独立完整重放、篡改拒绝和保全的全部要求。A 未通过不以短采样成功
   调度正式长跑，B 的独立 helper 只作能力预检。旧完整上下文包络跨调度结论原样保留。
7. 优先推进现有原指令执行链的真实边界。禁止在等待后的地址另起执行根、补写返回值、
   游戏结果或调用栈来宣称 A 通过。局部根级实验必须明确其输入、范围和未连接部分，
   不能计为连续消费。新原生执行只使用 F 盘隔离 Windows 客体，不要求用户操作宿主机。

## Risks / Trade-offs

2026-11-13 REA路线纠正：既有57项是原指令执行器的完整客体状态，完整raw64/隐藏段缓存
是原机上下文导入路线的附加合同，不能要求每条实施路线先取得宿主特权状态。保留前者
及全部独立重放/当前原生回执要求，停止扩建child-VEH完整现场搬运。下一候选为同一
当前所有者中执行原56E110/421F50、真实TLS和每线程叶路由；只合并helper PID不算通过。
按 docs/terminal_rea_wait_route.md 的60分钟离线、一次30秒无UI、16MiB证据关口执行，
原生准入尚未通过。后续用户已选择宿主方案，历史VM限定不覆盖该选择；需占用交互桌面
仍须新的事前告知和有界授权，本轮不启动游戏。原八项任务和验收标准不变。

- 当前独立场景根缺少外层祖先 → 不伪造返回地址；按真实调用来源扩展，并保留未接通状态。
- 原等待忽略 API 失败 → 独立验证事件所有权、等待成功、对端原调度动作及 OS 线程锁归属。
- 大前缀重跑耗时 → 在有界探针确认依赖后才跑完整证明；新代码静态/有界失败不触发小时级重试。
- 前缀旧原生寿命已经结束 → 恢复 RAM 仅作诊断，绝不标为原生接续或完整验收。

## Migration Plan

该单元起始于 `codex/connect-terminal-wait-and-battle-exit`；按用户后续要求合入主分支，之后默认沿用当前分支。各阶段保留实际未完成任务；仅全部适用验收完成才归档。每个连贯单元满足既有验收和体积规则后提交并自动 push；合并其它分支仍须用户明确要求。收尾同时报告 Git 新增体积、全部新本地证据及清理情况。
