# Design

## Context

见proposal.md。上一单元在第三句纹理仍活时冻结PC290，随后明确析构；新的续接必须发生在该析构之前，不能恢复已经关闭的原生助手。原配置4指向layer7，复用原前两句对象；先以固定R2 descriptor/Release契约执行原首行纹理析构，layer5第三句和原肖像仍保留到验收结束。

## Goals / Non-Goals

Goals: 完整原任务的确认等待/无输入对照/采集按下解除/松开、原43/44控制和第四句字体/栅格到403BD0首指令之前；保留六分支来源、全部CPU/内存/队列和原调用栈。

Non-Goals: 新原生输入、第四句纹理创建/上传/显示、后续opcode30角色9、原外层线程/世界同寿命连接、历史堆复原、Godot或R3/R6整体完成。

## Decisions

1. 不修改已验父工具，在其原第三句补充析构根之前附加续接；前序字体/原转换/就绪及CRT寿命仍完整执行，最后继续原第三句/肖像/堆锁清理和正常助手退出。
2. 原生采集仅写键盘对象raw_device的256字节，另声明原4113D5片段所需EBP/ESP和stack receiver。原指令更新完整A00h对象并与独立键盘公式比较；不写派生键位、鼠标、PC/wait或计数。
3. 继续使用原425DE0、40DB90、40DC80和454CF0根；末次完整任务只在自然第四句CreateFontA处暂停，再沿原栈执行原字体/CRT/栅格到自然新纹理入口，绝不新起独立VM或字体游戏根。
4. 新增自有离屏字体/测量DC/绘字DC/DIB，原测量token仅在API边界翻译，新DIB使用无重叠客体映射；原405160先析构旧首行纹理，必须验证原字节计数自然减少，父工具的Python验收条件明确纳入该合法减少，不写回游戏计数。与第三句服务分开所有权，原第三句服务和纹理不提前关闭。
5. 验收边界冻结后明确补充恢复选入对象并释放第四句GDI资源；这不是第四句handler自然返回，暂停记录中的句柄随后失效，下一单元应重新执行建立有效资源寿命。
6. 独立重放全部原指令/API/写入/完整CPU映射与队列，独立重画原始ANSI第四句三阶段像素；六分支无输入保持与按下/松开顺序和原控制分派均核对。

## Risks / Trade-offs

- 重新播放采集误当作新系统输入 → 固定两个已验原生流身份和raw字节，只声明客体中的采集回放。
- 输入绑定掩盖派生修改 → 验证前/仅raw绑定/原处理后完整A00h及全部映射，独立重放明确的寄存器/stack设置。
- 边界资源在补充清理后不可继续 → 原始边界数据与补充释放分开记录，不声称纹理/handler/世界自然返回。
- 新纹理依赖未验 → 停首指令，不伪造对象/响应或复用不同像素的历史上传冒充新原生验证。
