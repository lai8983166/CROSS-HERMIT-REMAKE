# Design

## Context

父验收b54ab995...停PC312、角色9CreateFontA首指令前，第四句纹理仍有效；续接必须插在第四句补充析构之前。原配置7选择角色layer4，姓名源a5eca8bda677与SC009固定来源已知，原CRT域可继续分配，不恢复旧缺失堆。

## Goals / Non-Goals

Goals: 六分支完整原姓名/肖像/任务及原动画自然就绪，到下一脚本43首指令前的PC332/wait0；正常资源与原记账闭环，并有全状态独立证明。

Non-Goals: 新OS输入、实际draw/Present、后继对白/世界与原外层线程同原生寿命集成、历史堆复原、Godot、R3/R6整体完成。

## Decisions

1. 不改父源文件；在第四句原403730补充析构根前附加角色9续接，保留先前冻结的自然字体边界。新资源、原向量/计数均由原指令产生，不写PC/wait/输入/计数，不新增独立VM或字体游戏根。
2. 角色9姓名使用单独的新自有离屏GDI，单独客体DIB地址；所有格式化/字体/转换/删除体均原代码。姓名及肖像实际D3D8资源使用另一自有隐藏设备，第四句设备保持存活，声明两套平台资源域，不声称原生单一renderer。
3. SC009只读接口固定安装/私有文件身份和原相对路径/只读参数，实际打开/测长/完整读/关闭；平台缓冲翻译到客体，后续源堆调用前按既有协议同步实际原CRT所有者。既有助手的SC004限制与源代码保持不变。
4. 复用原分配/链表/调试保护、向量/记录构造、512行原memcpy、文件原释放和原handler/完整任务；原请求/两个队列复位/task根最多200次更新至自然就绪，按实际次数记录，不以旧角色常量覆盖新结果。
5. 边界后明确补充原新肖像容器析构与姓名纹理析构，归还新增CRT向量/像素记账，再第四句、旧第三句/肖像及原堆锁清理。新GPU/测量DC正常退出，失败日志/实际清理单独留存。
6. 独立原指令/API/写入与全部CPU/内存/队列重放；新文件读回、源DX格式/像素、姓名新GDI及独立转换/新GPU读回互校。父Python验收仅适配新增原生叶调用/实际资源清理或记账预期，不改游戏状态；有额外原资源释放则明确记录。

## Risks / Trade-offs

- 原生资源域混淆 → 每个当前对象/指针/句柄有唯一所有者及类型映射；旧历史接口不传Windows。
- 地址重复或资源限额 → 保留两个新角色纹理到最终边界，明确原析构后退出；不静默替换原函数或伪造接口。
- 动画未自然就绪 → 有界保留全部状态，查原条件；不清wait或修改计数凑合通过。
