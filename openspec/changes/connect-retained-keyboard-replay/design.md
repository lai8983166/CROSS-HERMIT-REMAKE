# Design

## Context
冻结完整任务报告将三个原逻辑案例推进至PC248/文本就绪等待；已接受的原生输入报告包含两个独立进程的完整键盘对象和原始256字节设备状态。参见proposal.md。

## Goals / Non-Goals
在纯客体中以原机器码连接这两类来源：自然等候文本就绪、进入确认等待，原键盘处理派生采集状态，完整任务解除确认并到达后继指令边界。至少三案例×两采集流。既有报告/检查点只读；不声称新现场输入、实际新资源寿命、完整线程调度/世界/GPU或完整R3。

## Decisions
- 先逐指令复核冻结完整任务前缀，恢复原矩形祖先、原初始化覆盖、完整CPU和全部逻辑映射；只使用明确记录的平台输出。禁止以当前after生成期望。
- 原4113D5–4116A4设备读取后指令区直接作用于同一客体键盘对象；宿主只声明原生采集的256字节设备输出和该区所需调用帧，不写派生位/PC/wait。独立公式预测整个A00h对象并核对源写入范围。
- 每次使用原425DE0请求消化、原队列复位、完整454CF0；没有新增独立4CE8F0根。新平台调用只允许与冻结调用相同语义/参数及内存前提的空IMM和空字符串查询，明确标为记录回放。未支持接口直接报错，不替代原游戏函数。
- 完整任务自然返回后观察VM；下次任务以原分派进入下一条opcode30处理函数时保留自然栈/完整CPU边界，第一条handler指令未执行。该边界明确保留给后续资源/场景工作，不冒充后继handler完成。
- 新执行保留逐原指令与完整写入摘要、所有内存映射端点和CPU；独立验证从冻结来源重建并重放。无输入对照与采集按下/松开严格分离，不把旧原生PC当旧脚本预期PC。

## Risks / Trade-offs
- 保留状态依赖已结束的图形助手：新工作只作客体平台记录回放，不复用原生句柄、不提交GPU或OS输入。
- 异步采集并非原子快照：只选独立证明已确认的0/按下/松开样本，原始256字节清晰标识其来源；不把时间采样等同完整设备调用轨迹。
- 尚未支持的新平台/游戏路径：原样保留失败边界，不伪造成功。

## Migration Plan
独立前缀文件、固定父报告身份、保全/回归/严格规格，更新总规格本单元事实并归档，本地提交无push。
