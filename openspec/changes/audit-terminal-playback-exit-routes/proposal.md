# Proposal

## Why

连续战斗已产生原终局选择，但条件VM通过不能代表正式对白/等待和任务退出完成。R5/R6需要可追溯的终局路径清单，避免以旧模拟UI返回值接线或把脚本名当作退出语义。

## What Changes

- 覆盖安装目录全部45份战斗脚本，对原五种结果协议槽位逐项记录存在/空标记、完整指令、控制流、条件/播放分支和等待依赖。
- 从原EXE提取操作码分派、任务脚本握手及退出链的精确指令证据，关联当前T0004实例实际选择到后继依赖。
- 严格区分来源推导、已执行前驱和未执行播放/退出；对不支持或不完整编码明确列缺口，不假定全部槽位动态可达。
- 独立重建清单、负向篡改检查、相关回归、前驱/原资料保全及总规格同步，形成可复核的后续接线顺序。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。落实reverse-engineering/completion既有R5/R6来源覆盖和验收要求，仅新增研究工具、证据及文档；skip_specs为true。

## Impact

不修改冻结执行器、原游戏/资源/存档/检查点或Godot。本change为全语料终局路径研究，不执行终局UI或原生外层任务，不据静态可达推导宣称运行完成。目标2026-11-20和全部必需范围保持。
