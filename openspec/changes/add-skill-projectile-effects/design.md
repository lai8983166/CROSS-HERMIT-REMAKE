## Context

原版 `UnitCtrl.cpp` 在战斗初始化时只加载 `data\\DxAnim\\Efct.bin`。`UnitAnim.cpp` 将四位全局动画号拆为千位程序块与后三位动画号：`2042` 映射到 block 1 / animation 42，`3027` 映射到 block 2 / animation 27。技能明细表 `0x611538` 每行 0x10 字节，同时驱动单位动作和四类视觉阶段；攻击表 `+0x1A` 则进入 `48B2E0` 玩法效果分派，并非视觉资源索引。

现有 `fx_export.py` 只导出 `01E.BIN`，运行时也把攻击表 `hit_effect` 暴露为 `effect_id`。共享 DxAnim 解释器能够处理一次性和普通循环时间线，但 `EFCT.BIN` 的持续施法动画会不断生成瞬态子动画，当前状态签名无法收敛。

## Goals / Non-Goals

**Goals:**

- 建立从原版技能明细表与 `EFCT.BIN` 到运行时事件的可审计数据链。
- 正确表达持续施法、释放/弹道、同步等待、命中和恢复阶段。
- 用技能 29 完成一条可测试、可目检的纵向链路。
- 保持普通攻击行为和战斗确定性不回退。

**Non-Goals:**

- 本轮不实现技能选择 UI、AI 全技能选择或全部技能的伤害/状态语义。
- 不为尚未证明含义的动画猜测名称，也不把独立 `##E.BIN` 作为运行时映射依据。
- 不在没有逆向证据时实现自动追踪、抛物线或碰撞型弹道物理。

## Decisions

### 1. 以 `EFCT.BIN` 和全局动画号为唯一视觉标识

导出 JSON 保存 `global_id`、`block`、`animation` 与时间线。全局号按 `block = global_id / 1000 - 1`、`animation = global_id % 1000` 解析，并用 EXE 映射表黄金样例验证。这样直接对应原版 `0x465140`，避免再维护猜测性的 `effect_ids → 01E` 表。

备选方案是继续逐个导出 `01E…53E` 并人工关联；这些档案不是运行时加载对象，且无法稳定解释全局号，因此拒绝。

### 2. 单独导出技能视觉描述表

新增 `skill_visuals.json`，每行至少包含技能 ID、`cast_action`、`release_action`、`recover_action`、`cast_fx`、`release_fx`、`sync_fx`、`impact_fx`、`shape` 与 `gameplay_effect_id`。字段直接来自 `0x611538` 和攻击表，不把视觉与玩法语义混合。

### 3. 持续施法动画导出为受外部生命周期控制的循环

解释器的循环状态签名将忽略已经终止、不会再绘制的瞬态子实例，并在根程序状态与活跃可见子状态重复时输出 `loop_from`。导出器仍保留最大步数保护；无法证明循环的动画继续报错，不以截断结果冒充完整时间线。

备选方案是对 2044～2051 设置固定帧数截断；不同施法时长会产生接缝和泄漏，因此拒绝。

### 4. 单位动作映射推广为通用 action 映射

复用已经验证的方向索引与镜像规则，导出 action 11～16 的 `skill_actions`。运行时按技能行选择 action，而不是为职业或技能写动画号常量。空动作由视图回退待机，不影响特效阶段。

### 5. 技能阶段由模拟层计时，渲染层只消费事件

模拟层创建带绝对逻辑帧的技能事件，并按导出时长推进：施法期间保持 cast 特效；进入 release 时终止 cast；sync 时间线即使无图层也贡献时长；impact 到时再结算/呈现命中；最后进入 recovery。渲染层根据事件阶段创建和清理特效实例，不自行决定命中时刻。

技能 29 作为黄金样例：action 12 → 2050；action 15 / 2098；3017（120 tick 空白同步）；3032 命中。首轮由数据驱动的演示配置或调试入口触发，不引入完整选择 UI。

### 6. “弹道”先保留源/目标语义，不猜测未证实的物理

释放实例携带源格、目标格与目标单位；动画自身有位移时照原数据播放。只有后续逆向证明某全局动画使用线性/追踪移动时才增加相应路径模式。本轮仍完整保留 `release_fx` 阶段和目标元数据，避免把静态法阵错误拉伸成飞行物。

## Risks / Trade-offs

- [持续动画的子实例状态可能仍不收敛] → 为 2044～2051 建立黄金测试，只有状态确实重复才输出循环，否则停止实施并补充 VM 语义。
- [`EFCT.BIN` 导出会显著增加资产体积] → 首轮只写出技能 29 及测试依赖动画引用到的帧，同时在 JSON 保留可扩展全局映射；后续可增量扩大白名单。
- [技能 29 没有移动型投射物] → 本轮验证完整释放/同步/命中阶段与源目标元数据，不声称完成追踪弹道；后续以明确含移动语义的技能扩展。
- [旧 `effect_id` 调用方语义变化] → 迁移为 `gameplay_effect_id` 与分阶段视觉 ID，并保留普通攻击零值回归测试。

## Migration Plan

1. 扩展解码器与导出测试，再生成 `skill_visuals.json` 和 `EFCT` 资产。
2. 扩展单位动作映射，确保现有移动和普通攻击黄金测试不变。
3. 迁移战斗事件字段和特效加载器，保留旧数据缺失时的安全回退。
4. 接入技能 29 演示入口、自动测试和人工目检；失败时可回滚新 JSON 与运行时分支，不影响普通攻击。
