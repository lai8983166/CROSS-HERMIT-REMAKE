## Context

现有导出器把块0/块1的 10B 指令解包为 `{frame=-i16, dur=尾i16}`，再由 Godot 按单帧
序列播放。反汇编已经给出不同的数据链：块0指令的 opcode0 包含四个 12 位描述符索引，
描述符表再给出最终图像、偏移与时长；opcode1 创建块3子动画。方向选择函数把映射表结果的
高/低字节作为块号/动画号，并把表项第二字节低两位作为镜像标志。移动调用方传入动作号3。

当前共享解码器同时服务单位和攻击特效；输出 JSON 是 Mod 接口，运行时不读取原版二进制。
工作区存在大量仅 CRLF/LF 差异，实施时必须按文件精确暂存，不能批量提交。

## Goals / Non-Goals

**Goals:**
- 建立与原版动画指令、描述符和方向表一致的离线解释器。
- 输出渲染就绪、可编辑且能表达多图层/循环的 JSON。
- 单位移动八向与动作生命周期可由黄金样例自动验证。
- 共享解码器修复后重新验证攻击特效，不让旧错误产物进入归档。

**Non-Goals:**
- 本变更不修复 `battle.gd` 的双扣血问题。
- 不在 Godot 内实时读取原版 BIN 或 EXE。
- 不为尚未触达的音效 opcode 实现音频播放；但解释器必须正确跳过且保留时间轴控制语义。

## Decisions

1. **离线解释动画程序，运行时只消费渲染时间轴。**
   导出侧解析块0～块3程序与块4描述符，以有界解释器模拟 program counter、等待计数、循环、
   终止和子实例。每个 tick 收集父子实例的可见层，并把连续相同画面压缩为
   `{duration_ticks, layers[]}`，记录 `loop_from`。相比在 GDScript 重做原版 VM，这更容易做
   字节级黄金测试，也保持“运行时只读 JSON”的既有架构。

2. **逻辑帧使用图层数组，保留旧单帧输入兼容。**
   新 schema 的 step 含 `duration_ticks` 与有序 `layers`；layer 至少包含 BMP `frame`、`x/y`
   偏移和镜像信息。运行时仍接受旧 `{frame,dur}` 作为单层简写，避免现有 Mod 数据立即失效；
   官方导出物全部升级为新 schema，并在 `_meta` 标明版本与 tick 单位。

3. **方向/动作表从原版常量导出为数据，不在视图硬编码。**
   导出工具依据已定位的表A、表B、布局表及移动调用方动作号3生成可审计的方向配置；
   `unit_sprites.json` 保存解析后的八向选择和镜像位。罗盘到原版 dir 的关系用角度查表和
   实际坐标约定验证，并以黄金测试固定。当前的 `+5`、`off=块1` 路径全部移除。

4. **动作键驱动独立动画时钟。**
   视图为每个单位缓存 `(state, compass_dir, selected_timeline, start_frame)`；键变化时更新
   `start_frame`，当前 tick 由 `battle.frame-start_frame` 计算。这样速度档仍由 sim 时间控制，
   同时消除全局帧和单位序号错相导致的随机起步姿势。

5. **黄金样例验证最终语义，不只验证索引范围。**
   测试至少固定 A0A/B1A 的块0 #11～#15：原始10B指令、解出的描述符号、块4最终 BMP帧、
   时长及镜像方向。另验证所有当前布阵单位八向齐全、所有图层帧界内、复合样例的父子层在
   同一 tick 共存。攻击特效重新导出后固定默认斩击的最终帧序列。

6. **提交按可回退边界拆分。**
   依次提交“原始解码+黄金测试”“单位导出+视图”“攻击特效回归+文档”。每次只精确暂存
   本任务文件，避免把全仓换行符噪声带入提交。

## Risks / Trade-offs

- **[解释器遇到未见过的控制流或不收敛]** → 设置状态重复检测和明确步数上限；报出档名、块、
  动画号与 PC，禁止静默截断。
- **[描述符某些绘制属性语义仍未完全命名]** → 原值进入 JSON 并保持渲染所需行为；只有经过
  反汇编或黄金画面确认的字段才命名。
- **[新 schema 影响手工 Mod]** → 运行时保留旧单帧记录兼容层，并在文档给出机械迁移示例。
- **[攻击特效默认动画因正确解码而改变]** → 不沿用旧 anim id 的视觉标签，重新逐帧生成预览
  和目检后再确认 `default`。
- **[方向坐标约定误配]** → 同时用角度 dir 查表、帧姿态条带和确定路径截图三方验证。

## Migration Plan

1. 先落地原始解析器与不写产物的黄金测试。
2. 升级单位导出 schema，重新生成单位 JSON/PNG并接入兼容渲染器。
3. 跑八向确定路径截图与全量 Godot 测试；异常时可回退单位数据和视图提交。
4. 重新生成攻击特效，更新其黄金断言并完成用户目检。
5. 修正文档结论；确认无旧字段调用后再考虑未来移除兼容层。
