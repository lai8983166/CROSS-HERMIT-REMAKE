## Context

见 proposal.md。当前模拟以 30Hz 运行，DxAnim 资源为 60Hz；五个串行 stage 同时承担动作、视觉与玩法，导致特效结束冒充人物完成。477980 的 AI 状态 0x16 等待 unit+4，46BCC0 切换动作时清零该标志；释放入口调用 46C990 扣 MP，46C930 在开始前检查 MP。必须继续追踪动画更新写回与事件队列消费者，不能仅把 36 tick 替换成 47 tick。

## Goals / Non-Goals

Goals：用可追溯的信号驱动样例，分别输出人物、视觉与玩法事件；固定逻辑帧回放可复现，事件包含原始 tick 与量化帧。

Non-Goals：不推测未还原的技能效果，不扩展 AI 自选技能、全职业时长修饰、装备快照或主动取消。死亡/撤离仅接入已证明的实例清理范围，已脱离的同步效果不跟随人物阶段粗暴清除。

## Decisions

1. **证据先于调度替换**：先定位单位完成标志写入，以及 DxAnim 0x04/0x08 事件到同步/结算消费者的链路，记录 C1A 与 D0A 的技能 22/29 多方向实际信号。只加时长会保留错误因果关系，不采用。
2. **时间线信号独立导出**：共享解码器保留有效节点事件的 tick、类型、来源和自然结束/循环信息；不从可见图层数量猜测事件，空白帧也能发信号。终止 tick 必须与解释器一致，而不是盲目求和。
3. **人物与事件实例独立推进**：演员生命周期为 cast → release → recovery → idle；释放信号派发同步/玩法/命中特效，视觉实例各自自然结束。保留现有事件字段兼容视图，但阶段事件增加明确类别，结果按实例 ID 关联，不能假设数组最后一项就是当前施法。
4. **时间域明确**：保留 60Hz 原始 tick，30Hz 帧使用向上取整；同帧信号按原版已证实的处理顺序稳定派发。测试分别验证资源 tick 与模拟边界，公开 30Hz 量化限制，不声称逐原版 tick 已完全等价。
5. **MP 为单独事务**：显式请求不足则拒绝；释放开始读取原版费用并扣一次，合法范围钳制。目标 MP 伤害与源费用分开事件记录；不引入原版没有的释放前重检。
6. **中断只按证据**：死亡/撤离准入拒绝；已启动技能的取消查明原版清理函数后实现。依附人物的持续 FX 与已进入独立队列的同步实例分开清理。重复样例按技能演员状态等待并处理资源不足，不用所有视觉时长之和推算下一次施法。

## Risks / Trade-offs

- [事件发生在子节点或空白帧] → 导出时读取节点标志，不仅仅读渲染层；用原始记录与解释器事件规则交叉测试。
- [旧固定帧测试锁住错误时序] → 保留资源/目标/效果回归，时序基线仅以新增证据改写，并在审计文档解释变化。
- [动画映射缺失/循环] → 明确未支持状态，不把待机回退当完成证据，不静默臆造原版时序。
- [有限 MP 使循环样例停播] → 日志给出拒绝原因；不通过隐藏自动补蓝制造假原版行为。
- [原版死亡后独立效果继续结算] → 中断与独立队列分开，测试覆盖已释放和未释放两种情况。

## Migration Plan

按提案、证据、资源信号、调度、MP/中断、回归的小里程碑分别提交。重新导出数据并运行 Python、Godot 离屏测试与 OpenSpec 严格校验；视觉对比聚焦动作恢复与特效重叠。旧接口保留可兼容字段，不要求用户重新配置技能目标。需要回滚时针对独立提交执行可恢复的 revert，不覆盖用户改动。

## Open Questions

未证实的主动取消、目标途中丢失、技能 29 的玩法效果和特殊职业时间修饰保持后续逆向范围，不由本次样例猜测。
