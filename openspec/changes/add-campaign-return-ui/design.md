# Design

## Context

见proposal的动机。现有BattleReturn/CampaignResultState支持两条冻结场景5样例，主场景只运行战斗。源样例的规定角色为3/4/9，默认战斗有四名无目录ID的友方，不能自动用默认终局套用源战果。

## Goals / Non-Goals

**Goals:** 会话适配器拥有单一内存目录和冻结路线；Control页只读适配器视图，操作经显式阶段推进。页面可在1024×768查看、滚动和键盘聚焦。

**Non-Goals:** 通用学校菜单、编班/排课、四单位战术准备、实际脚本调度、原版存档与原版战术终场生成。

## Decisions

- 独立演示模式复用已有布阵的前三名友方及敌方，赋予源参与者ID；不更改默认布阵JSON。避免默默裁剪普通游戏战果；默认模式退出后完整恢复。
- 会话适配器启动时核对两个来源JSON的已归档SHA，只保留规则、初始目录、事件/任务/准备输入与结果上下文。运行时不消费expected_after等输出，完整输出仅测试使用。改用自动下载或任意来源解析没有必要。
- 阶段为battle→result→settled→school。实际Battle结束才建立返回门槛及准备/初始化战果；确认完成结果；进入学校执行已捕获返回数据链。确认/学校已完成时返回成功且无再发布。页面切换不触发事务。
- CanvasLayer上的工具栏与可隐藏PanelContainer，VBox/HBox/ScrollContainer组织结果及学校页。完整面板可见时拦截地图快捷键及鼠标穿透。窄范围输入错误显示可恢复错误页。
- 学生以稳定ID显示；尚无可信名称映射则使用“学生 #ID”，职业和道具同样使用ID，不编造名称。展示等级、七属性/七池、准备包及战利品等已确认字段。

## Risks / Trade-offs

- [样例被误认为本地战斗结果] → 持续显示演示说明，单独标记本地胜负/逻辑帧与源路线。
- [重入重复奖励] → 单会话阶段守卫，所有按钮仅调用适配器；重复动作和切页回归核对版本/日期/日志。
- [面板挤压或拦截默认操作] → 伸缩容器和滚动，默认只显示小工具栏，渲染检查两种页面及恢复默认状态。
- [中文字体缺字] → 使用可用系统中文字体回退，实际渲染后检查文字。

## Migration Plan

无数据迁移或外部写入。分阶段提交适配器、页面/入口及验收；删除演示入口即可恢复原窗口。冻结原版来源文件保持不变。
