# Design

## Context
见 proposal.md。现有 run_case 经原MAIN事件启动源场景，无任务/VM快捷根。Computer-use sky 能列出真实窗口。

## Goals / Non-Goals
验证真实系统输入引起原输入状态变化并跨越确认等待，至少两个独立进程；不把合成系统输入称为人类物理操作，不宣称完整R3或战斗完成。

## Decisions
- 只复制并扩展冻结采样器，复用其桥/资源初始化与正常关闭。扩展采样时间180秒/12000样本，记录完整输入对象、鼠标派生字及原代码/IAT。
- 使用唯一返回的私有exe窗口，优先 computer-use 的 press_key(space)，获得用户明确授权后也可使用受限Win32后备，每次先观察后输入再刷新。Python只读已有输入/VM状态，不写按键、PC、等待值或线程寄存器。
- 等待opcode51/wait1持续稳定，再发布只读停点通知；确认输入后捕获实际键盘状态和后继PC。无输入稳定窗口是同进程对照。
- 验证器复用旧结构契约时明确投影“启动阶段无输入”的旧字段及扩展采样上限；新顶层输入声明单独严格验证，不把旧验证的false字段作为全程无输入证据。
- 两场景时序不同，由原等待条件驱动；不降低等待或修改脚本。完整调用链采样不等于逐原生指令跟踪。

## Risks / Trade-offs
- 输入脉冲短 → 高频采样保留前/当前/边沿缓冲；没有采集证据不能验收。
- 旧Direct3D窗口捕获失败 → 使用已定位窗口和内存证据，保留实际工具错误，不要求用户重复操作。
- worker可能在清理中被原管理器取消 → 沿用原生命周期核对，不称自然回调返回。

## Migration Plan
新增文件独立于冻结历史；完成后保全审计、回归和严格规格、同步总规格事实，归档change并本地提交，无push。


## 历史：2026-10-22输入交接与待授权后备

工具输入期间停止原线程Suspend采样，改为有界异步只读输入/VM采样，前后仍保留完整原生状态。这个阶段的观察不能冒充原子全状态或指令轨迹。原窗口本轮激活成功，系统记录短按但原DirectInput和VM仍未转换。

Win32保持扫描码后端已准备，包括自有Job/窗口/私有exe/前台检查、120ms保持和异常释放；默认关闭。因computer-use技能的JS-only规则，已经向用户提出明确例外确认，当时答复尚未收到。未授权前禁止调用后端；现有computer-use原任务2.1不降低标准、不标完成。若用户同意，使用该受限后端验证同一系统输入到原脚本转换目标，再在本change内更新方法说明。


## 2026-10-22用户授权

用户明确答复“允许启用后备输入（推荐）”，授权限定自有原版前台窗口、扫描码39h保持120ms和松开、不修改游戏内存。来源记录为analysis/school-native-dialogue-authorization-v1-20261022.json。使用既有--held-input开关继续同一原版系统输入到确认转换目标，非缩减验收范围。两个源场景仍分别独立运行并核对完整来源、真实按下/松开、PC跨越和清理；不能仅以SendInput返回值完成任务。


## 2026-10-22解锁后验证结果

检查发现LockApp.exe为实际前台，停止操作并由用户解锁。新增只读桌面守卫，在启动和归属检查前拒绝锁屏/不可访问/不同输入桌面；不操作安全桌面。解锁后held-76-v4与held-77-v2均记录原键盘0→80h→0、源确认PC跨越和交接后普通循环，并经原游戏/窗口/Job清理无强制终止。独立验证器核对原始完整字节与输入回执，不以缓存边界或SendInput返回代替实际转换。工具启动/adopt实验只作失败诊断，不是正式验收路径。完整R3和保留执行仍待后续change。
