# Design

## Context
见 proposal.md。现有 run_case 经原MAIN事件启动源场景，无任务/VM快捷根。Computer-use sky 能列出真实窗口。

## Goals / Non-Goals
验证真实系统输入引起原输入状态变化并跨越确认等待，至少两个独立进程；不把合成系统输入称为人类物理操作，不宣称完整R3或战斗完成。

## Decisions
- 只复制并扩展冻结采样器，复用其桥/资源初始化与正常关闭。扩展采样时间180秒/12000样本，记录完整输入对象、鼠标派生字及原代码/IAT。
- 使用唯一返回的私有exe窗口和 computer-use 的 press_key(space)，每次先观察后输入再刷新。Python只读已有输入/VM状态，不写按键、PC、等待值或线程寄存器。
- 等待opcode51/wait1持续稳定，再发布只读停点通知；确认输入后捕获实际键盘状态和后继PC。无输入稳定窗口是同进程对照。
- 验证器复用旧结构契约时明确投影“启动阶段无输入”的旧字段及扩展采样上限；新顶层输入声明单独严格验证，不把旧验证的false字段作为全程无输入证据。
- 两场景时序不同，由原等待条件驱动；不降低等待或修改脚本。完整调用链采样不等于逐原生指令跟踪。

## Risks / Trade-offs
- 输入脉冲短 → 高频采样保留前/当前/边沿缓冲；没有采集证据不能验收。
- 旧Direct3D窗口捕获失败 → 使用已定位窗口和内存证据，保留实际工具错误，不要求用户重复操作。
- worker可能在清理中被原管理器取消 → 沿用原生命周期核对，不称自然回调返回。

## Migration Plan
新增文件独立于冻结历史；完成后保全审计、回归和严格规格、同步总规格事实，归档change并本地提交，无push。
