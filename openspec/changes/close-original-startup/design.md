# Design

## Context

总规格R1；前缀工具和原始证据已覆盖窗口创建消息129/131/1/5/3/24/70，下一条70尚未执行。捕获映像含旧游戏和字体缓存指针，其真实堆不在本实验内。历史change已归档。

## Goals / Non-Goals

Goals: 完成原窗口创建/发布并追清继续启动所需的游戏/缓存初始化和寿命。每个连贯单元包含来源、执行、验证和说明。
Non-Goals: 本change不承担R2的完整绘制/连续VM接回，不修改Godot，不改旧存档或私有VM，不伪造平台/游戏返回值。

## Decisions

- 复用同一原代码执行器和x86辅助程序；扩展通用消息准入，兼容路径在同一寿命内连续执行，真正的未知对象/接口才构成停点。
- 初始化状态必须来自原始PE加载语义或原启动指令。区分捕获的运行中映像与新进程初值；任何新启动输入须在第一条原指令前明确声明并来源验证，不能在待执行边界清零旧全局。
- 新的辅助程序协议只在需要真实新接口时版本化。保留冻结的旧辅助程序源/二进制/报告；共享Python执行器向后兼容地增加显式启动输入，历史源码由Git追溯。新的验证器共享独立重放核心，重复回调复用路径，避免一条消息一套模块。
- 开发中跑新增路径；稳定功能边界运行相关回归/严格规格/保全。来源、原始轨迹和状态校验随连贯成果提交，不以指令/提交计数替代功能验收。
- 完整工厂/COM/音频初始化采用同一自有原版进程从头正常执行、只读采样其调用栈和实际对象图，与原代码分支交叉核验；窗口前缀继续保留已验证客体轨迹。这样复用真实系统环境，不为每条平台接口另造桥，也不声称完整工厂已在客体逐条重放。此方法不改变R1功能范围，R2仍须在有效资源寿命内接回原连续VM。
- 原游戏正常清理与自调试保护层的进程退出码分开验收。实际WM_CLOSE、原析构栈、游戏/主对象/缓存清空和窗口结束必须有证据；保护层C0000354不得冒充WinMain返回或全进程零退出。错误输入探针明确标为隔离来源分支验证，不报告成实际系统失败。

## Risks / Trade-offs

- 原始EXE可能经过打包，静态加载含义需验证 → 查PE节布局与初始化/解包来源，不能只把捕获值改成零。
- 原生默认处理可能嵌套回调 → 在客体执行循环外服务原生请求，显式保存/恢复调用上下文及受保护栈，验证真实深度和顺序。
- 游戏工厂可能引入音频/COM/资源依赖 → 追踪真实来源和接口契约，在本启动范围内逐项闭合；不把尚缺的关键依赖计作完成。
