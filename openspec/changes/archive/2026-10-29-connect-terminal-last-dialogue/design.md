# Design

## Context

动机见proposal。固定父为9846d8c1封存的multiline验收，PC294/312 wait1，543/546完整任务，14/15创建世代，10/10张存活纹理。原全量来源使用流式读写，父原始证据及完整前向不改。

## Goals / Non-Goals

完成两分支最后一组原文字到下一确认及实际补充清理，原父全内存/57CPU/摘要保持。后续清层/淡出/终止与实际显示、外层原生同寿命及奖励不属于本有限单元，继续保留缺口。

## Decisions

- 继承父类及已验四根/原键盘片段/全部允许代码。胜利1行重写图层4 record0；超时3行均重写图层7 record0/1/2。原44只清count，早期text7_3的record2及世代49一直存活，第三行实际也由原405160→403730先释放该旧世代。正式峰值10/10、15/18创建世代，继续使用父10张/32创建助手和原有清理根，不提前销毁其它live资源。
- 初次把count1误解为只有record0存活，导致预期超时替换数2，而真实数为3；来源v1在PC350两次保持后计数守卫拒绝，139,673,200字节完整诊断、原输入代码及11张实验helper精确字节保留。容量11平台探针本身通过11成功/12拒绝/显式释放，但不证明原VM需要11；正式来源v2回到原10助手。实验helper及探针仅供失败复现，不作为正式来源或容量验收。
- 父GPU序号已接近GDI6A001000，继续旧序列会发生跨域风险。新phase开始时保留完整prefix ledger及next，确认48001000–49501000整段与所有实际映射及GDI/CRT域无交叠后，将仅后续分配起点设为48001000；原AddressSpace.guest算法不改。每创建7身份、各独立域，最多21身份；旧guest/native对应、源字节与next的历史声明均不改。新起点及完整非交叠/分配序列由独立验证另验，不能合并或过滤旧地址差异。
- 当前全部CRT/GDI/GPU回执及所有像素独立审计；原引擎按完整PE初始映射、RX/RW和原快照分区恢复，保留全部原指令/写回调。先预检固定父四累计字段，再核对父全前向、新阶段全内存/57CPU/队列/原摘要和实际清理；两新完整原生实例复现。
- v2的父ML前缀原指令数、原写次数和code SHA一致，但write SHA不同；逐条原生GDI回执确认新字体复用了已删除字体的原生句柄整数，旧按整数永久分配的投影错误地复用了guest地址。v2完整诊断和精确代码输入保留。v3在第一条GDI调用前安装按创建寿命/角色的类型投影：固定父计划只包含句柄参数位置、角色和guest身份，由独立审计逐项对照固定父原回执；当前native句柄、所有API调用/状态/内存输出/像素仍实时执行并完整保留。新阶段每次owned创建分配新guest身份，原生整数只允许在前寿命成功删除后重用；SelectObject返回必须是该DC当前选入的真实对象。最终slot表只表示最新寿命，全历史以逐调用绑定和lifetime表审计；测量DC的补充释放另记，不称游戏退出。父完整内存/CPU/摘要依然严格保持，不以投影说明豁免差异。
- 沿用已验流式JSON/Gzip写入及有界流式解码，所有值/字段/原始payload完整，不抽样、归一化原堆/表面或过滤重试。失败记录独占新文件名保留，大证据本地及仓库外逐字节备份，Git只留代码、必要小报告和大小/SHA/位置。

## Risks / Trade-offs

- 新域与未列出的客体映射冲突 → 对完整实际before映射逐区验证；当前/新GDI和全部CRT/GPU身份及span另查。发现冲突直接失败，不掩盖或挪旧对象。
- 父执行漂移 → 正式helper原字节不变，固定父完整前向/累计摘要严格预检及独立重放；实际所有者hello和build绑定原10张版本。实验11张helper与正式使用清楚分开。
- 长任务/内存与存储 → 默认主Agent完成，串行监督必要来源/专项/证明，流式处理全量数据；不为运行命令创建子Agent。
- 原ANSI空白/乱码 → 保留全部实际GDI/texel，分别报告纹理结果与实际显示缺口，不补画。

## Migration Plan

只新增工具及研究记录；保全通过后更新总规格实测进度，本地提交、归档并封存worktree/index/HEAD逐字节一致结果，不push。旧源、helper、归档、资产、存档及私有检查点不改。
