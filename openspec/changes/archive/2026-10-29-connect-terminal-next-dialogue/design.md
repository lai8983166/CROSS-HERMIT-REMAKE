# Design

## Context

动机见proposal。固定前驱为6838f7b3所封存的replacement验收，当前9/7张纹理、10创建世代；PC230/226 wait1，父全部前向保持。主机ABI身份跨进程可变，原生已释放地址可重用，原始堆/LockRect字节必须保留。

## Goals / Non-Goals

目标是完整四根任务及原键盘片段推进到新确认，资源创建、同record替换、像素、原释放与完整内存/57CPU/累计摘要可独立复现。完整终局显示、原外层同寿命及任务退出/奖励不在此有限单元验收内，保留总规格缺口。

## Decisions

- 继承当前来源类，新增独立阶段命名空间；不改父代码、允许范围或IAT。绑定新raw256采集周期，由原键盘片段写派生A00，原任务写PC/wait。
- 各新创建使用单独投影域，保留前驱guest地址及replacement域顺序。域与原record、创建序号及实际wire绑定，避免已释放宿主地址重发影响guest布局。原AddressSpace分配算法与原始native payload不变。
- v1实测超时前驱FU文字在wire66重发已释放的原生纹理地址，使原overlay表复用guest64E01000，而固定父期望新65601000，后续少一格。该次layer5 text4的texture.pointer使用overlay-followup-text-pointer单身份域，新地址和重发地址均由原guest算法占同一next槽位，vtable/methods仍共享原overlay。
- v2指针已匹配，但wire68的bits改为新原生地址，原overlay又新分配65701000，固定父则复用旧64F01000表面，后续多一格；Code摘要和原指令/写次数相等，Write摘要不同。v3明确用overlay-followup-text-bits绑定已原Release的text5 guest表面，旧/新均128x32、pitch256、8192字节，核对同record、成功零引用释放、创建先后与没有其它存活资源占用；不推进next或新增guest区域。此为已退役表面的声明alias，并非原guest新分配算法。当前native bits无论重发还是全新，原始表面字节均作为实际API输出写入该既有区域，原转换代码继续执行。
- 父admission保留原代码对象，只以当前平台类允许这两个明确前缀域；父源文件不改。独立审计逐wire绑定额外alias条目和旧真实释放/表面范围；跨历史投影表只合并这个明确的额外角色绑定，保留所有guest地址、原始payload和实际ledger。前驱全内存/57CPU/全部累计摘要及中间页仍严格一致，不借此忽略任意差异。
- 在当前父admission返回后、ND阶段前，来源立即从固定小型父proof比较四个完整累计摘要字段并打印实测结果；失败当场拒绝并保存诊断。独立验证仍另验全内存/CPU/轨迹，不把此快速摘要检查当作全部验收。
- 完整复用当前CRT/GDI/D3D8 helper，超时SC002只读载入；由原角色处理器产生姓名、IMAGE及就绪。继承容量仍须严格满足，不能通过清空旧对象取得空间。
- 独立验证先核对固定父前向全部内存/57CPU/轨迹及中间页，再从实际平台回执独立执行新增原x86；复核当前全部native所有权和像素、实际原清理。两新完整实例重新创建资源复现累计摘要，不投影历史清理CPU/SHA。
- 独立回放按来源先一次映射完整PE镜像，再装载快照并恢复来源RX/RW权限和全部原分区边界。逐片新建镜像backing曾在56CF01的rep stosd产生一次提交前重试，CPU/内存相同而多一条指令和一次写回调；该失败原样保留。恢复来源内存布局后超时新增112帧的57CPU、130个全内存边界和原始摘要全部一致，不丢弃回调、不改计数或源字节。
- 全量来源先落本地，再仓库外逐字节备份；Git只存代码、必要小报告、路径/大小/SHA。历史原证据及原资产/存档/检查点不变。
- v2新来源使用JSONEncoder.iterencode分块UTF8流写至独占xb文件/GzipFile，保留JSON分隔符、原字节及换行/压缩等级；v1及失败记录原样保留。避免一次构建整份JSON和UTF8副本。

## Risks / Trade-offs

- 十张live容量边界 → 从实际wire核对峰值、世代及全部原释放，超界直接失败。
- ANSI/ACP936字形与Big5原文不符 → 保留原字节/字体与真实GDI输出，不以补画宣告正确显示。
- 大来源和重放耗时 → 串行生成，后台监督；主Agent负责测试/提交/归档，一名独立来源实现者负责复杂新增来源，避免重复全面实现。
- 前驱清理观察可能包含新世代 → 按创建wire/record实际寿命分类，父前向冻结、当前清理另验。

## Migration Plan

只新增工具及研究证据；验收后本地提交，标完任务并归档，最后封存worktree/index/HEAD逐字节一致记录。失败诊断另存，旧文件不覆盖，不push。
