# Design

## Context

见proposal.md。采用已验cold.data与固定原.text；旧保留链节点缺失，不能接入新堆假称历史恢复。

## Goals / Non-Goals

Goals: 六个原保留分支从自然IMAGE入口，在同一个新平台助手寿命内完成原读关、两次分配和原向量/容器构造；逐指令独立复核到首个肖像403BD0边界。

Non-Goals: 旧堆历史恢复、原生同寿命完整游戏、GPU上传、外层世界、Godot及全CRT启动。目标日期及总范围不变。

## Decisions

1. 私有独立验证器副本观察已验第一步IMAGE状态，保留完整内存和CPU。选择此入口可重新自然打开文件，不绑定或复用已关闭文件句柄。
2. 在独立cold客体执行57B9D0及576F60；只投影CRT调试控制/链统计、48槽锁表、四静态锁及heap/mode的有限字节，记录每区原值及来源值。其余全部内存和CPU严格不变，79FC74游戏记账保留。保留对象都是旧域，禁止新堆free它们。
3. 新原OS叶调用使用既有无窗口助手，按类型翻译新堆/锁，完整同步原调试头、用户区及保护区。代码/IAT不改，CRT和游戏函数不代用。
4. 原IMAGE入口→403BD0是连续执行，无新游戏根。边界后为实验清理明确调用原428AD0释放两个新域块，再原576FA0/57BA60销毁；这些补充根不计IMAGE完成或handler返回。
5. 独立重放器单独验证投影域、全CPU/内存、原文件内容/容器84字节记录、原栈、原分配链和所有平台接口所有权。保留旧证据及失败记录，追加新路径，不改已验工具。

## Risks / Trade-offs

- 新CRT域具有新request/统计 → 始终标注reconstructed，旧历史未恢复；游戏计数只由原代码增减。
- 未来原free可能访问旧域 → 当前严格所有权边界拒绝；本单元只释放新域两块。
- OS堆/锁物理细节不能与客体地址相同 → 类型翻译和完整镜像记录，不声称原生物理地址逐字节还原。
- 初次纹理边界仍无肖像GPU输出 → 明列下个功能边界，R3/R6不标完成。
