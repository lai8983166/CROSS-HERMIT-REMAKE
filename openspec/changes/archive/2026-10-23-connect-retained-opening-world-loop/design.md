# Design

## Context

父验收70549e14...停在原task自然返回后，所有当前字形/角色/CRT资源在补充清理之前仍有效。循环调用点4539EC→454CF0、4539FB→453F10、453A0C→46B470、453CB0→422360均有原机器码来源；父驱动的返回哨兵不等于原循环栈。

## Goals / Non-Goals

Goals: 在同一资源域内声明一个原普通循环根，分段沿原栈观察后继task控制、世界门控/入口/返回及首个合作等待；不能合法跨过的真实拥有/平台依赖也是明确调查结果，必须给出可重放的精确停止位置和修复前提。

Non-Goals: 伪造4539F1调用者栈、替代游戏/CRT函数、恢复旧缺失堆、回写门控/计数、强行返回协作等待、真实原外层线程/事件集成、实际绘制、Godot或R3/R6完成。

## Decisions

1. 继承父包装器，在首个新增字形补充析构之前插入连续执行。父工具/报告不改；记录业务入口与各原生所有者仍存活的证据。不得在父清理结束后加载快照冒充当前源生命周期。
2. 原request和两队列复位保持既有声明根；新增4539B0根必须完整声明receiver/stack/return，只设置该调用必要寄存器/栈，不恢复原普通循环调用者CPU。后续入口/返回点以连续段执行，不新增单独46B470或VM根。
3. 停点优先自然世界调用前、世界调用后和首个422360协作等待首指令前。必要时在未知平台入口、未拥有CRT释放入口或真实未映射访问处停止，完整保存原指令/写、CPU/映射、调用链、门控、队列和访问身份。不能人为制造更早停止来省略兼容调用体。
4. 已有当前平台调用照原ABI/所有权执行；新平台依赖先核来源与生命周期，能在现有域合法重建则同单元继续。原字段、旧失效句柄、缺失旧堆或线程事件不能靠新值替代。末端补充原资源析构和正常助手退出与业务完成分别验。
5. 独立验证从已验父来源重放原链及新根；针对调用者/receiver/世界门控/停止理由、全部源指令/写和完整状态做破坏测试。六分支必须分别绑定来源和结果，关闭世界门只算原早退，不算单位更新；等待首指令未执行不能算原调度恢复。

## Risks / Trade-offs

- 原循环首次触及父驱动未覆盖依赖 → 在原边界保留机器码/对象/所有权缺口和下一修复动作，不注入返回值。
- 新控制可能自然释放父资源 → 记录原释放并调整私有Python验收预期，避免二次释放；不改游戏计数。
- 父链独立复核成本 → 复用只读来源缓存，六分支按独立进程组验证，平台助手构建目标按PID隔离。
