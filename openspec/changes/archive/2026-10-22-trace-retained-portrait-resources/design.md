# Design

## Context
见proposal.md。上一单元六分支均在4C61C0首指令前保留真实任务/VM栈。既有角色来源模型已解释配置8和名字体前缀，但该路径尚未接入恢复后完整任务。

## Goals / Non-Goals
完成安装45份脚本的结构/指令清单和全部opcode30静态资源依赖，并在六分支连续执行到原名字体API入口。静态出现不代表可达性或规则实现；动态表达式保持未决，新字体/图像加载和完整外层世界不在本单元验收范围。

## Decisions
- 复用并严格约束原容器/VM段格式，独立重走字节边界验证清单；保留每条指令的脚本/段/文件偏移、长度和源分派块。END单独按分派前特殊处理记录。
- opcode30四个原表达式逐一分类；literal配置与角色解析原38字节配置表、姓名指针表和60字节角色资源表，核对实际文件身份。非literal表情表达式不伪造常量，不声称完成其运行时解释。
- 固定上轮验收及运行报告，复用冻结独立重放器并在其完整映射核对处采集客体快照；只在私有Python globals副本中增加只读捕获，不改变旧模块/游戏函数。六源分支各自验证后连续执行到原IAT5920A0指向的CreateFontA，禁止新根/复位。
- 新前缀无平台返回，字体调用第一条指令不执行。来源模型预测完整八区域、配置/层/对象初始化，原调用栈推导核对14参数；独立CPU复核所有新源指令、全部写入、完整映射和CPU。

## Risks / Trade-offs
- 全脚本清单含不可达代码和空段：明确是安装包静态全量，不改写为完整主线动态覆盖。
- 字符编码/无效表项：保留原Big5字节与源指针，拒绝无界字符串/缺失文件/错误配置，不猜测名字或路径。
- 父CPU含元组、回放器有既有元数据契约：复用已修正的冻结接口，JSON只作规范化比较，不写回旧记录。

## Migration Plan
独立前缀产物，相关测试/说明与每个功能单元同提交；最终全链保全、严格规格、总规格事实同步和归档，本地提交无push。


## 全量来源发现

326条opcode30中320条为20字节四参数，6条为12字节两个参数（T0080/T0090）。原handler固定读取四DWORD，不能把后继指令字节作为声明参数；本单元保留完整读取窗口、缺失参数数和未决标记。可达性/实际解释仍为R6覆盖缺口，原文件不改写。4210个四字节段实际是dmf空标记，非零DWORD。
