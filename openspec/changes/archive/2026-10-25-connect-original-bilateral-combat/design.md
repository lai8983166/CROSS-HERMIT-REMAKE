# Design

## Context

参见proposal.md。前驱EnemyMachine的游戏指令guard、调用ABI、TLS真实平台叶接口及37区域快照已经验收；其独立Model把UNIT/TARGET固定为攻击者/受害者，不能用于证明双向战斗。

## Goals / Non-Goals

**Goals:** 同一世界寿命中两个单位自然选敌、各至少两次命中及后继世界帧；四职业和有限关系/搜索/被动对照，显式记录双方身份及伤害事件。

**Non-Goals:** 完整世界字节独立预测模型、死亡/奖励、主动技能、所有AI策略、原生渲染和保留任务同寿命集成不由本单元完成。

## Decisions

- 只派生自己的观察器和run；source_code/call/base_call沿用冻结前驱，不修改原代码/IAT，不在运行时注入游戏状态。双方路径包在首个世界前经原初始化；开始后仅完整世界根。
- 双方HP预声明为1000，四职业同职业对练，敌方/玩家关系矩阵逐向显式声明。分别观测双方475270请求和48AAE0、48AD03、493450边界及实际HP store；命中必须标注攻击者和受害者，不能依靠固定地址含义推断。
- 完整内存/CPU、所有原轨迹摘要和每个中间状态要求新实例相同。独立函数契约验证直接使用原函数入口参数、完整记录和随机种子作为输入，验证选敌候选规则/物理判定及HP队列结果；这些入口是观测到的检查点输入，不声称由独立全局模型预测。
- 以每方两次命中和其后完整世界帧为停止条件；对照固定预算。被动一方不被声称已验证自主；不把停止测试循环写成游戏停止命令。
- 复用原preservation递归审计，固定上一验收SHA及32份不可变产物；只有总路线图与.gitattributes可追加。

## Risks / Trade-offs

- [双方交战可能进入新分支] → 原指令范围默认拒绝，必要时仅按反汇编来源声明新增完整函数区间，保留未支持边界；不加返回代用。
- [入口检查点模型不证明整个世界状态的独立推导] → 报告独立范围和原实例重放范围，不将两者混称为完整独立世界模型。
- [短时间内HP恢复掩盖伤害] → 同时验原命中/事件包/真实写入和完整HP变化，不仅比较最终HP。
- [声音概率和攻击标志改变共享随机流] → 沿用实际CRT/TLS，校验完整重放和每次物理判定的种子/抽取次数。

## Migration Plan

新增工具与报告；无产品部署。任务全过后同步总规格实测状态并归档，Git只本地提交。冻结前驱和所有存档，回退可移除本单元新增产物而不重写历史。
