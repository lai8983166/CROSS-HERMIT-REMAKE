# Design

## Context

参见proposal。冻结的live-terminal验收证明同实例生成选择，但其余原生UI/脚本/退出尚未执行；已有全脚本指令库存可复用，不能把静态库存重复计为新运行覆盖。

## Goals / Non-Goals

**Goals:** 形成全部45脚本的五个协议槽位矩阵、每个存在脚本的严格CFG和双模式分支分类；精确关联原任务握手/结果动画/整理的来源和已验实例停点。

**Non-Goals:** 不把协议槽位存在等同实际主线可达，不虚拟满足UI/输入/音频/世界等待，不声明原生任务退出或奖励完成。

## Decisions

- 复用已冻结容器解析和分派解析，新增独立边界/编码/CFG重建器交叉检查；报告保存每个命令原字节、完整来源SHA、边和未知边，不靠编译器名称决定实际语义。
- 五种结果的槽位2/5/8/11/14来自原场景4及454AF0表。其它场景仅作候选协议清单，明确未证明其动态调用；空dmf和缺失都保留。
- 对标准167/8/166/11前缀只精确求解WORK模式0与1的分歧，其余外部状态条件以保守CFG两边表示，动态/不支持的控制操作记录未知边，不跨越后宣称确定结束。
- 以Capstone解码完整原4539B0/454CF0/453F10等边界的指令字节和直接调用；关键握手写、时钟/动画/473860调用用固定地址/指令断言，必要数据表单独取原字节。后继状态以来源规则解释，不采用旧ExitEmulator模拟回调结果。
- 冻结前驱43项及固定验收文件SHA，并递归原资料审计；新报告严格验证结构/汇总/来源和未完成标记，输出必须为新路径。

## Risks / Trade-offs

- [槽位被当成全部实际可达结果] → 每行标明候选协议，只有前驱实际观察T0004的选择单列运行证据。
- [短指令/动态跳转] → 按声明字节取数据，越界读取依赖单独报告；未知控制边不计算为证明终止。
- [静态可达被当作执行完成] → 显式分离模式来源推导、保守CFG及冻结实测，所有R3/R4/R5/R6继续未完成。
