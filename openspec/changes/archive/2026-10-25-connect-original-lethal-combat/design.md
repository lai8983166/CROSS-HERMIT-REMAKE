# Design

## Context

参见proposal.md。BilateralMachine已验37区域/完整世界与双方身份，但以两次命中停止。旧Model把受害者固定为TARGET，不能直接证明玩家/敌方互换后的死亡记账。

## Goals / Non-Goals

**Goals:** 六例：职业1/3双方各作致死受害者四例，玩家保命阈值1的256帧对照及不敌对96帧对照；死亡例双方至少各出手一次，记录存活状态到移除并多留完整世界帧。之后以实际世界记录执行原473860，核对原结果输入字段。

**Non-Goals:** 自动外层任务设置胜败选择、奖励/经验/道具发放和场景转换不由补充输入根代表。完整世界逐字节独立预测模型不新增；其它死亡类别/特殊AI/技能仍待验。

## Decisions

- 私有派生执行器沿用已验guard算法/call/API实现。死亡受害者HP/容量70，对手1000，双方回复间隔32767；两次39伤害自然致死，避免初始低血量在第一次交战前死亡。双方反应目标/技能均−1。
- 增加原死亡命令、战场移除和命令11入口观察，原记录/统计/HP写入保留身份；使用明确入口输入独立预测计数回绕、击杀归属、HP/恢复及死亡状态转换，不从返回结果生成期望。
- 地图、已加载资源和正常战术模式仍为首根前声明。结果数组增加独立拥有页7F5000h，输入身份与单位槽1记录匹配；原473860为显式补充根，TASK+174保持0且结果选择0只表示尚未生成选择。
- 结果门108B3A继续为0。保存原46B470门后调用与原473860/4307B0来源，明确世界死亡不会自动越过任务/交互门；不以设置该门、清零原任务或代用函数结果冒充胜败完成。
- 所有拥有区域/CPU/中间状态及原轨迹由新实例精确复现；独立验证仅限列明函数契约。冻结前驱51项产物并递归保护原资料。

## Risks / Trade-offs

- [玩家死亡可能包含寿命/物品分支] → 按实际原记录输入验证分支，不将敌方固定模型套用；遇未声明PC保留失败后查来源。
- [结果数组清理访问超出旧拥有范围] → 首根前对原镜像已映射页声明拥有范围/权限，仅开放原结果字段写范围，保留全页原字节，不改变旧快照定义。
- [结算选择0被误写成胜利] → 报告来源是TASK+174，条件键只说明敌对存活筛选，R5整体不标完成。
