## Context

B 线已实证：MAP01.MAP = 变长表区 + 48 页 256×256 X1RGB555（0x4D8 起、0x20000 步长、行优先
0.488 vs 列优先 -0.012），`analysis/map01_atlas.png` 即该算法产物。main.gd 已有 SubViewport
烘焙管线（静态层一次成像）与 world 坐标系。

## Goals / Non-Goals

**Goals:**
- 观感跃迁：sim 底图 = 原版纹理，零运行时解析（PNG 离线生成）
- 数据视图保留（核对工具价值不丢），三态切换
- 产物可再生成、可入 git（脱离游戏目录运行）

**Non-Goals:**
- 不做单位形象（原作 D3D 模型无 2D 帧；立绘/模型方案独立 change）
- 不做地图卷动/缩放、UI 皮肤、音频
- 不追求全 50 张地图批量（工具支持编号参数，按需生成）

## Decisions

1. **图集独立 PNG 而非多页纹理数组**：单张 2048×1536 PNG 加载与烘焙都最简单；
   Godot 4 上限 16384 无压力。备选（每页一 Texture2D 数组）省内存但复杂化烘焙，弃。
2. **页起点 = 签名扫描而非硬编码 0x4D8**：B 线发现 MAP01 页起 0x4D8、MAP02 0x404——变长表区
   使偏移不通用。工具内置 dist=512 行相关 >30% 扫描（已验证算法），首命中且连续 pageX×pageY
   页均为合法起点才算通过（自校验）。比维护偏移表稳健。
3. **X1RGB555 解码 bit15=alpha 照搬 render_dximg 语义**：地图页实测 bit15 100% 置位，解码时
   忽略 alpha 位（不透明输出），与 B 线渲染一致。
4. **叠加态数据层 alpha 0.45**：经验值，可看清单位路径又不淹没贴图；做成 main.gd 常量
   （非 JSON——观感参数不属 modding 数据面，调好为止）。
5. **三态用一个 `_base_mode` int + 烘焙管线双画**：烘焙 SubViewport 时同时产出"数据层"纹理
   （现状）与加载图集纹理；_draw 按 mode 顺序贴 0~2 张。不重复烘焙、切态零成本。
6. **贴图坐标系 = 数据坐标系**：图集 2048×1536 px == world 包围盒 (px_w×px_h)，cell_to_world
   的 32×16 菱形天然落在贴图像素上——叠加态即对齐验证（spec 场景）。

## Risks / Trade-offs

- [签名扫描在异常 MAP 上误定位] → 决策 2 的连续性自校验 + 尺寸断言；失败报错而非错图
- [PNG 入 git 体积]（MAP01 约 2-4MB）→ 可接受；50 张全量时再议 LFS
- [贴图与数据层错位（坐标系假设错）] → 叠加态肉眼即检；若错位，回头核对 BIN px 头与页拼合
  方向（row-major 已实证）

## Migration Plan

新增工具+资产 + main.gd 底图段改造。回滚 = 还原 main.gd、删 assets 两个文件。
