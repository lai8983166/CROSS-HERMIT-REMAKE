# Design

## Context

父验收417f7961...的PC332/wait0仍持有角色9姓名/肖像、第四句和更早的逻辑资源。其后补充析构仅为实验收束；接续必须插在这些清理之前，后续原退场可能自然释放同一资源。

## Goals / Non-Goals

Goals: 六分支在有效父CRT/GPU资源域内执行T0005代码PC332–496的剩余26条，观察真实脚本终止/后继转换边界，完成原资源退场及独立验证。

Non-Goals: OS输入、实际draw/Present、原外层线程与全世界同寿命连接、Godot或R3/R6整体完成。仍复现ACP936的原ANSI行为，不将其称为Big5乱码修复。

## Decisions

1. 私有Python包装器在父角色9业务边界后、补充清理前续接；父冻结工具不改。允许后继原指令自然释放旧纹理/向量，旧补充析构变为原代码检查后的空操作；只适配Python验证与记账预期，不恢复CPU/内存或改计数。
2. 六句文本的每次字体栅格操作使用独立自有GDI与互不覆盖的逻辑DIB；纹理使用新自有GPU域，逐对象所有权/代际/描述/锁定/上传/读回/Release明确。父真实对象仍由其当前所有者操作，旧固定接口仅作为已声明平台契约，不冒称当前GPU。
3. 通过原完整request/两队列复位/task推进；两组确认均先至少两次无输入控制，再绑定已验76/77原始device数据，执行原键盘处理片段和完整任务消费，最后原处理松开。输入派生字段/PC/wait/计数不由宿主重置。
4. 每个区间保留源指令/写摘要、全CPU/映射、全部有效队列、脚本解码/层/文字索引/动画和资源状态；动态指令起点与源代码段26条对照，文字4–9和末端19等语义由原执行核实。
5. 原收尾可能触发后继世界入口。到自然脚本终止及完整任务返回，或首个明确的新转换调用首指令前形成边界；记录全栈与来源，后继世界体保持未执行，不用返回桩使其通过。整体R3/R6状态不随有限脚本单元归档而完成。
6. 独立从父来源重放并对所有新增API/写入/完整CPU/映射/队列互校；字体独立新GDI重画、转换独立计算、全表面新GPU读回。对资源自然清理增加对应校验，原计数/堆/锁和全部当前平台助手正常退出。

## Risks / Trade-offs

- 跨域旧对象在收尾中自然析构 → 根据接收对象而非共用方法地址分派，明确自然与补充调用，拒绝已结束/外来所有者。
- 未知收尾依赖 → 留完整源失败证据，在原边界调查来源；不伪造对象、跳过函数或改原指令。
- 六分支/完整重放耗时 → 共享不可变来源缓存，单元覆盖全部剩余对白，父证据保持冻结，不拆成逐句change。
