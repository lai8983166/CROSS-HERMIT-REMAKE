## Context

add-unit-sprites 已落地精灵渲染（基色）。侦察定案（2026-09-18）：
- 块7[0] == 身体帧内嵌调色板（dist=0）；帧 1/0（特效帧）与全部块7 距离 ~51 → 特效帧
  各自内嵌调色板，不走换色系统
- 40 张表两两距离结构：0-8 相近族、{10,19,28,37}/{11,20,29,38}/{12,21,30,39} 等步长 9 分组
- 视觉：第 1 行=装备大改（蓝银/金/暗褐），第 2 行起=头盔/盾色轮换，#9=黑影红边特殊版
- 块8（帧数+1×u8）与帧高相关性弱（高帧 0.43 / 矮帧 0.17）→ 语义仍开口

## Goals / Non-Goals

**Goals**: 块7 导出为数据；sim 运行时换色（精确 RGB 匹配重映射 + 缓存）；
battle_setup 阵营/单位 palette_id 配置；回退完备。
**Non-Goals**: 引擎侧 palette 选择字段定位（记开口，battle_setup 手配即用）；
#9 黑影版的游戏语义考据；特效帧换色（各帧独立调色板，无系统换色）。

## Decisions

1. **换色实现 = GDScript 运行时 Image 重映射**（不动导出资产）：帧 PNG 是基色 RGBA，
   加载时按块7[0]→块7[k] 的逐条目 RGB 精确匹配替换像素，`ImageTexture` 缓存按
   (anim_id, frame, palette_id) 三元组。理由：保持帧资产单一来源；40×导出变体
   PNG 会爆炸（~8 万文件）；shader LUT 需要索引通道而 PNG 已无索引。
   缓存键含 palette_id，换色零额外每帧开销。
2. **换色表独立文件** `data/unit_recolors.json`（不并进 unit_sprites.json）：
   帧表 ~2MB 已不小，换色表语义独立、改动频率不同，分开可独立替换。
3. **阵营默认配色进 battle_setup.json**（`faction_palettes: {"0": id, "1": id}`），
   单位级 palette_id 覆盖阵营默认。选哪两个 id 落配置（可改），工具的预览图供挑选。
4. **匹配失败像素保持原色**：特效帧/抗锯齿边缘不在块7[0] 表内的像素不动，
   保证任何 palette_id 下渲染正确性。
5. **导出器与 unit_anim_export 分离**（单 concern 小工具），但读取同一容器解析约定。

## Risks / Trade-offs

- 精确 RGB 匹配若帧 PNG 有压缩损失会失配 → PNG 无损，可控；实测以块7[0] 为准
  （导出时帧就用它上色，匹配率应 100%，工具校验并输出匹配率）。
- Image 重映射首帧延迟：每 (帧,色) 一次 O(w×h) 表替换，128×128 量级毫秒级，缓存后无感。
- 40 色/档 × 10 档 = 400 条 JSON（~1.2MB）→ 可接受；预览图帮助人肉选色。
