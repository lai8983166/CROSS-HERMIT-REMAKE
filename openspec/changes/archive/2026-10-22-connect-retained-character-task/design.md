# Design

## Context

见proposal.md。上一单元将六分支保持到IMAGE返回4CC0D2；新域中的向量/纹理尚有效，旧历史堆仍不完整。旧动画模型证明30/45/60边界和第三句参数，但不是无代用的完整任务执行。

## Goals / Non-Goals

Goals: 六分支沿原栈完成资源handler及首次完整任务，再通过原IME请求消化、两种原队列复位和原454CF0任务推进至动画就绪及第三句CreateFontA首指令之前；独立核对原状态、入队及资源寿命。

Non-Goals: 第三句字体创建/显示、新GPU或OS输入、原外层线程/世界同寿命连接、缺失历史堆复原、Godot或R3/R6整体完成。

## Decisions

1. 重用已验原冷CRT初始化、335字节限域投影和原IMAGE连续读取/构造/返回；同一助手寿命持有新向量直到全部任务验证后再原容器析构。
2. 第一段不设新根，沿原调用栈返回；之后每更新明确声明425DE0、40DB90/40DC80与454CF0原根，不增设4CE8F0根。原派生计数/PC/wait均不由主机写入。
3. 平台仅支持已验原IMEnull/输入空串查询和已固定类型/角色的纹理回执，注明历史回放；第三句Font首指令停止。保留代码/IAT原字节，不用展示或CRT函数代用。
4. 核对原展示/入队函数、队列全记录和先后顺序。若路径实际访问静态资源，先补齐其来源契约；不能凭画面缺失而忽略必需依赖或跳过原函数。
5. 独立验证器以完整原指令/写入/CPU/映射和原调用栈重放；旧动画来源模型仅独立比较状态/等待边界，展示代用不构成证据。保留失败探测日志、所有原始资料及存档保护链。

## Risks / Trade-offs

- 向量/纹理仅为新资源域或已验平台回放 → 说明资源重建及历史回放，不声称实际GPU/原生同寿命游戏。
- 原静态资源或队列可能暴露缺口 → 检查原读取和分支，拒绝伪造对象/全局清零或代用函数结果。
- 后续新根可能被误当作完整外层循环 → 逐根明确原入口/receiver/参数/返回，只声明完整任务及原调用链。
- 补充清理不能代替流程 → 仅在验收边界后执行原容器析构、锁堆销毁，和前向进度分开计数。
