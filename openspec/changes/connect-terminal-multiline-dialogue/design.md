# Design

## Context

动机见proposal。固定父为322b23e5封存的next-dialogue验收，PC256/268 wait1，累计484/508完整任务、11/13创建世代及9/10存活纹理。前驱FU指针单域与已释放表面alias、完整PE初始映射/RX-RW/分区恢复已验，必须保留。

## Goals / Non-Goals

目标为一组确认到下一组确认的全部三行/跨层对白、原替换与真实平台资源及原清理可复现。完整终局显示、原外层同寿命、后续确认和任务退出/奖励不属于本有限单元，仍列缺口。

## Decisions

- 从父完整来源重跑；继承原四根、原允许代码与CRT/GDI/GPU helper，不另起VM/handler根。新采集回放周期由原键盘代码更新A00，原任务写PC/wait。
- 每次新文字创建使用独立投影域，按原配置/图层/count导出的record及序号绑定；保留父全部guest身份与地址、原HeapAlloc/LockRect/padding。三次创建的最多21个新身份低于GDI域；不复用已退役原生指针冒充旧对象。
- 原44只清count，原405160调用403730释放被重写的record；胜利第三行新增record2，超时两个不同图层各重写record0。逐创建核对真实所有权及容量；补充原清理只覆盖实际新增仍存活record，不能清空旧对象腾容量。
- 独立引擎按已验单一完整PE backing、来源RX/RW和快照分区恢复；原指令/写回调全部计数，不过滤重试或归一化摘要。先核对固定父全部累计摘要，再验父全前向及新阶段全内存/57CPU/逐帧队列/原轨迹。
- 当前全部原生协议与全部像素另验；两新完整实例复现前向及实际清理，不投影历史清理CPU或SHA。ANSI/GDI实测空白或乱码保留，不补画或宣告正确显示。
- 来源沿用分块流式JSON/Gzip写入，独占新文件名。全量来源先存本地并做仓库外逐字节备份；Git只留必要小报告、大小/SHA和位置。
- 正式v1来源为1,816,900,562字节；首次整份JSON读取在UTF8解码时MemoryError，尚未开始动态验收。当前验证器改用有界输入缓冲的流式容器解析，单个字符串/数值仍交标准JSON解码器，仅共享完全相同的不可变长字符串；完整值、所有字段/像素/内存和原始gzip字节保持。Unicode、转义、跨块边界、数值、重复键和坏格式均与标准解码语义对照测试；不新增依赖、不重生成来源。

## Risks / Trade-offs

- 原helper最多10张live、32次创建 → 严格按每个wire核对实际峰值及释放；超界失败，不扩大容量或提前销毁。
- 前驱原生地址重发影响投影 → 冻结已有角色绑定，父全字节/CPU/摘要严格预检；任意新差异另诊断，旧证据不覆盖。
- 完整重放耗时和大证据 → 主Agent串行监督必要来源/专项/最终证明，复用独立算法，不为命令执行新建子Agent。

## Migration Plan

新增工具和研究记录，全部验收后更新总规格实测进度、本地提交、归档并封存worktree/index/HEAD一致记录。父文件、原资产/存档/私有检查点保持，不push。
