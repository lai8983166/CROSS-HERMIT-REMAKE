# Design

## Context

见proposal。资源前驱已归档，前向边界是完整原任务返回的PC52/WORK剩余59；其后补充清理不可复用。本单元通过子类在前驱admission返回与其资源清理之间连续执行，保留已验初始化、源守卫、原根ABI和真实当前平台。

## Goals / Non-Goals

**Goals:** 完整任务自然完成剩余59次工作更新并继续终局VM至下一真实资源依赖；逐帧规则和当前资源完整重放可复核。

**Non-Goals:** 不独立调用VM/117或工作更新作为前向替身；不把资源入口停点称完整终局播放或实际画面输出。

## Decisions

- 原资源同寿命内扩展原队列复位→输入复位→完整任务顺序，执行至明确未初始化资源/API的首指令前，不写游戏派生值。
- 每帧保存完整VM/WORK/任务/输入、57项CPU、原指令/写入摘要和有效队列；只记录工作嵌套调用的紧凑原ABI/状态，避免将相同全内存重复塞入每条观察。
- 前驱PC52截面单独冻结，由既有独立模型验证；新增帧由独立整数/字节模型核对，整个最终映射及CPU由新实例重新创建当前资源重放。
- 前向冻结后复用明确补充原容器/队列/堆锁清理。原栈/SEH在冻结时保留，补充清理不冒称任务自然退出。

## Risks / Trade-offs

- [后继VM触及新依赖] → 保留准确来源、原调用栈和入口参数，不返回空资源或关闭绘制门。
- [截断余差被归一化] → 严格按648步长及原阈值/状态顺序验证，不把38880修成38912。
- [前驱和新增记录混淆] → 分别保存PC52前缀及续接后的完整边界，复核同一CPU/内存自然衔接。
