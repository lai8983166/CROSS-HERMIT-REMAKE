# Design

## Context

见proposal。父验收285de3c9...在原栅格仍有效时冻结403BD0，随后补充释放；新续接必须插入该释放之前并重新完整运行来源，不能恢复已关闭的字体或设备。脚本306/text3后直接312/op30(config7,role9,0,30)，不加入不存在的第四句等待/确认。

## Goals / Non-Goals

Goals: 第四句原纹理体、像素转换/GDI自然删除/完整任务，及下一原任务的角色9自然字体入口；全部原映射/CPU/队列/栈和实际新纹理像素可独立验证。

Non-Goals: 其他历史纹理的新原生重建、实际draw/Present、角色9字体执行/肖像加载、外层世界/历史堆恢复/Godot/R3或R6整体完成。

## Decisions

1. 不改父工具，私有工厂附加到第四句离屏资源close边界，在其真实GDI尚存时续接，完成后原删除的字体/位图/DC不再补充删除，仅补充测量DC。父Python验收适配实际清理数量和新增资源影响；不能伪造旧清理报告或写回游戏计数。
2. 复用未修改ImageD3D8 x86桥，为每个分支独立创建隐藏窗口/设备。仅在CreateTexture/GetLevelDesc/LockRect/UnlockRect/Release平台接口边界翻译旧逻辑设备和新接口/位地址；响应来自当前自有资源，全部请求/返回/身份及类型投影登记。
3. 实际锁前字节保留，原405A80沿原栈转换全部带，完整锁内存同步到真实纹理并读回；独立像素公式从新绘制的第四句三阶段栅格复现相同结果，包括未写区域保留，不假设分配填充恒零。
4. 继续原完整任务自然返回，再由原request/queue reset/task根到角色9CreateFontA首指令前；不新建独立VM、字体游戏根或宿主写PC/wait/输入。保存角色/配置/姓名来源与原栈。
5. 边界后补充原第四句纹理403730根验证计数收束；再父第三句、肖像、CRT锁/堆原清理，D3D设备/隐藏窗口正常close。部分角色9任务不计完成。
6. 独立重放所有新增原指令/写入/接口及每区间全映射/架构CPU/队列；嵌入前序验收时显式清空旧摘要缓存并仅适配Python预期。六分支来源、当前GPU回执与正常退出均逐一核对。

## Risks / Trade-offs

- 平台在锁屏下不可用 → 预检已经成功；若后续失败，保留实际失败/清理证据，不请求长期解锁、不宣称正常完成。
- 把新纹理当作完整原生renderer → 明示只有当前第四句的实际D3D资源，旧对象仍历史平台契约；没有draw/Present。
- 绕过游戏依赖 → 全部游戏/CRT体执行原指令，平台翻译只影响声明的接口输出，代码/IAT及游戏计数不改。
