# Design

## Context

原生完整启动、字体/设备、场景派生构造及422360等待契约已验；旧保留检查点不具备当前原生资源寿命。直接在空场景资料上恢复会退出，正式实验需原4E1B60初始化及源菜单可选76/77场景资料。

## Goals / Non-Goals

Goals：在完整私有原版副本内，原439E30请求16触发WinMain工厂和原调度器，真实CRT场景回调经加载进入普通4539B0循环，核对VM/世界计数及正常清理。
Non-goals：不宣称物理输入、保留旧VM原地恢复、完整游戏或R3完成；不把原生状态采样称逐指令/API追踪或像素验收。

## Decisions

- 完整复制原运行目录（包括独立SAVEDATA/OPTION.BIN），逐文件核对私有资源/原exe字节与不同文件身份；原版源码不改。再次核对实际运行进程exe属于私有目录，原存档保全独立复查。
- 复用冻结x86桥，另分配一参数cdecl桥，仅在4DA860返回后add esp4；白名单限定4E1B60、4DA860(76/77)、439E30(实际MAIN+10h,16)。不写已有游戏对象或虚表，不直接启动451670/4539B0。
- 轮询原事件/工厂发布/原主循环/实际工作线程，保留WOW64上下文、完整调用链、真实脚本头/PC/指针和场景世界计数。完整对象只在加载后几个关键停点采样；读写范围和采样数有界。
- 原退出使用冻结R1自有Job/HWND属性归属检查与正常WM_CLOSE；工作线程结束和游戏清理分开于保护层退出状态报告。原manager清理可取消仍在等待的线程，不能称自然CRT回调完成。
- 失败样本单列且排除验收；观察器在异常时不释放仍在执行调用桥的新内存，交由明确记录的自有Job清理。

## Risks / Trade-offs

- 实际加载受系统速度影响 → 按有意义的状态/计数边界有界等待，不用固定休眠推定完成。
- 与旧菜单/原线程并存 → 通过原MAIN事件请求和原49E2B0/49E540调度，记录真实链表/线程，不启动并发私有调度器。
- 全套资源复制占空间 → 私有副本复用，原资产与副本前后身份核验；仅复制目录中的SAVEDATA/配置允许原程序正常写入。
