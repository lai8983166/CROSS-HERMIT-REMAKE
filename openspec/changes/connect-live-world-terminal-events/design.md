# Design

## Context

参见proposal。已验LethalMachine负责新声明输入下的完整世界，TerminalMachine负责场景4条件VM/结果选择，但后者读战后快照。新执行器只复用其原体、守卫算法和平台接口，不调用快照装载构造路径。

## Goals / Non-Goals

**Goals:** 同一新实例内依次初始化、完整世界/计时、完整事件、首次终局请求、原结果整理和明确资源清理；七例覆盖敌我职业1/3、保命、非敌对及战斗前到时。

**Non-Goals:** 首次选择不等于死亡动画/移除已结束；不继续运行终局展示脚本或声称任务退出/奖励完成。主机明确调用完整世界与事件根，不称原外层4539B0/线程同寿命。

## Decisions

- LethalMachine首根前原声明为基础，直接构造一致TASK+190=CTRL、T0004/VM/工作区，不从任何战后文件恢复。固定父验收SHA仅用于保护与来源引用。
- 108B3A在首根前为1；415040原体返回实参1，467B60自然推进经过/剩余计时，计数到0由原事件优先级决定；门后交互读取明确无输入状态，不借用游戏函数桩。
- 每帧完整46B470返回后显式完整432100；原终局请求设置暂停和脚本忙时停止。保命对照执行192帧；中性可在首帧选终局，短时限3自然到时。记录首次选择时真实HP/命令/动画阶段和全部计数，不人为等候移除后才触发事件。
- 全部原指令/写入累计摘要、逐根摘要区间、逐帧世界/事件状态与57项CPU保留；分页复用相同字节，避免将数千万PC逐项驻留内存。新实例核对全部字节、CPU和摘要，不将摘要重放称独立VM/世界字节预测。
- 原边界契约核对双方HP/随机流/记账，新增独立原计时、事件条件/条件VM/任务请求及结果契约。Windows时钟首采/回放界限沿用已验方式，原TLS实际接口单独核对。

## Risks / Trade-offs

- [事件可能在死亡移除前成立] → 以首次原选择为终点并保留实际阶段，不能人为延迟或改活状态。
- [打开门暴露未执行提示/交互路径] → 核对原函数与精确写范围、保留诊断，执行原体；不关闭门掩盖依赖。
- [对象状态/观察数据量] → 首根前声明最小一致布局，观察器只读，分页及摘要保持全字节可重放。
