# Design

## Context

参见proposal。冻结世界执行器拥有完整46B470和250槽观察器，父独立模型已覆盖单次攻击准备、动画、命中与单位收尾。现有run仍在HP之后才进入世界根，需要私有重组驱动顺序。

## Goals / Non-Goals

目标为声明双单位/空交互下，从原6号请求到一次基础近战自然完成、8/9恢复或13死亡移除的连续世界链；每例最多192帧，再验一个完整终态帧。靶命令5/记录存活1为固定靶输入，不声称正常敌方AI或完整主线战斗。停止续攻的原请求与原世界消费分别记录。

## Decisions

- 私有继承既有构造、原观察器和清理，重写run；绑定后不调用独立475700/40A100/482A30/4918D0/493450。只执行世界根及已声明停止请求，所有派生字段由原代码写。
- 独立模型把准备/主附动画/事件/HP并入单位顺序；HP公式使用实际当帧回复后的当前HP，不能照抄旧独立前缀的初始HP。死亡后保留使用槽并继续核对下一原更新。
- 大字节字段按4096字节分页、SHA身份与原字节目录无损保存；小单位/记录与全部CPU保留原布局。重建验证长度/每页身份，独立模型比较全部字节的分页投影，完整拥有区和轨迹另作新实例复现，不抽样。
- 原指令准入使用同一声明区间的私有等价快速查询，只读原镜像保证代码不改；以与冻结守卫的实际执行对照及越界/原CC拒绝测试核对，避免长帧重复线性查区间。未知依赖仍拒绝，不能改返回结果。
- 父46份与递归资料冻结；全状态/真实TLS/回归/严格规格通过后同步总spec并归档。本次不改变既有验收工具。

## Risks / Trade-offs

- 世界内回复/动画顺序可能改变命中时HP与效果时序 → 分别记录实际事件/HP写和嵌套状态，按原顺序独立核对。
- 长帧报告大且重复多 → 无损分页加逐例处理，保留全字节与全帧，禁止截断或删除历史。
- 固定靶和停止续攻可能被误作自然游戏流程 → 文档明确首次声明和原接口调用，不将其计作原生输入、AI或胜败集成。
