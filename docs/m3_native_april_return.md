# 四月原档出击后的成长与返校

学校的「原档出击」可读取四月第 1、2、3 周已编班的原版 v7 学校档。战果页点击「确认战果」后，游戏结算本周、保存重制续档，并显示下周日期、累计经验、MVP、升级学生和获得的道具。返校至第 2、3 周可以继续出击；第 4 周可查看和重读本路线的最终学校记录。

重制续档扩展名为 .chschool，放在 Godot 用户目录的 original-school 子目录。通过「原档出击」文件选择器中的「重制续档目录」可重新打开。续档记录原始学校档路径、SHA-256、每场指令及返校状态摘要。读取时需要保留原始学校档；程序从它重放每场指令并核对摘要。重制程序不覆盖原存档。

## 战果进入学校的字段

同班师生的实际出击顺序、职业、属性、技能和关系来自 v7 数据。战场计算的时间档、清敌档、设施所属、伤亡和个人贡献用于计分及掉落。结算按班级和槽位顺序消化 20 份成长包，更新成长池、属性、等级和技能，以本次确定性种子 4660 计算技能抽取。确认时更新在籍学生的职业履历、本周记录、师生关系和 MVP 次数。换周处理职业开放、装备与技能清理、任务消费及下周开放。

返校界面投影学校状态。原版战后剧情、职务室和入校演出未逐段重放；下周先保留当前编组。三张地图的原版完整战斗与重制使用相同战术操作的对照仍待完成。本实现可从三份已经排好出击的根存档开始，网上下载的未编班第 1 周文件须在原版编成后才可出击。[冒险 3 和原版客体记录](m3_adventure44.md)

## 同一战场结果的原指令核验

验证器从各自根存档直接载入原版学校字节及角色区，再执行 4A7D30、4A6A10，复核参战者排列。把实际重制战斗结果送入原版 4BD210、4BCA40 和 4BBD40；后续 4C00C0、4C1350 和 4D3510 继续使用这些原指令生成的成长包和学校结果。核对逐人属性、成长池、等级、技能、职业进度及开放标志、装备、履历和关系，并核对掉落、库存、最佳学生与返校日期。MVP 次数按已核实的确认增量单独比较。[原指令验证器](../devtools/verify_native_april_return.py)

三个根档分别进行同输入原例程对照。每场检查 20 份成长包、35 名在籍学生、6195 个履历字节、2756 个有向关系及 360 个库存位置。
