# 技能编号关联审计（第一步）

`python tools/skill_link_audit.py 22 --unit C0A --direction N` 将同一个技能 ID 的攻击表行、演出表行、指定单位/朝向的动作映射，以及 EFCT 全局动画 ID 放在一份只读报告中。原始输入分别是 `prototype/data/attack_table.json`、`skill_visuals.json`、`unit_sprites.json`、`attack_effects.json`。必须指定单位资源包，以免误把某个单位的动作映射当成所有角色通用。

报告中的 `hit_effect` / `gameplay_effect_id` 是玩法效果编号，**不是** EFCT 动画编号。`effect_id_matches_attack` 只检查两份导出表的一致性，不证明效果分发语义。`targeting` 与 `target_filter` 保留原值，不在这里推断敌我性质。每个动作的顶层 `status` 表示当前 Godot 导出覆盖情况，嵌套的 `original` 表示原版动作表查出的块/程序号及其在原始 BIN 中是否存在；两者不可混为一谈。

状态含义：

| 状态 | 含义 |
| --- | --- |
| `exported` | 当前 Godot 资源 JSON 已包含这个动作方向或 EFCT 动画 |
| `valid_not_exported` | 全局 EFCT ID 在原资源程序块范围内，但尚未导出到 Godot |
| `not_exported` | 单位动作 ID 没有当前导出器提供的映射；不能据此断定原版没有该动作 |
| `no_exported_direction` | 动作有映射槽，但该单位该方向没有导出条目；可能是空槽，也可能仍需核实 |
| `outside_archive` | 全局 EFCT ID 越过目前解析到的程序块边界 |
| `none` | 表中编号为零 |

目前这个工具只审计已有导出链，**不**证明技能调度时序、EFCT 的施放位置、目标阵营、伤害生效时刻，也不替代实机差分。它的直接用途是定位编号关联的断点：技能 22 的 `2044`/`3027`/`2029` 已导出；action 31 已按原版动作表导出，但 E0A/E1A 的原始程序缺失；action 13 的北向映射在 C0A 有、D0A 没有，因此不能跨单位直接套用。

## 原版动作号的两级查表

`python tools/unit_action_table.py 31 --type-index 0` 可直接从 `analysis/hermit_game.exe` 解出原版的动作/方向表。`0x464D70` 按单位类型索引取得动作表指针 `0x60E850[index]` 和程序表指针 `0x60F070[index]`。`0x465040` 再以 `action * 8 + 0x610510[direction]` 读动作表的二字节记录：第一字节是程序表索引，第二字节低两位是镜像标志。程序表的 16 位值高字节为动画块号、低字节为动画号，然后交给 `0x409FF0` 播放。

`0x466C80` 用单位序号 `param_2` 在 `0x610538 + param_2*8` 取 `data\\DxAnim\\*.bin` 路径，同时把 `param_2 + 8` 交给 `0x464D70` 选择动作表。因此现在可以通过 `python tools/unit_action_table.py 31 --archive C0A` 直接查询资源包的原版动作映射。十个映射是：B0A=9、B1A=10、A0A=11、A1A=12、C0A=13、C1A=14、E0A=15、E1A=16、D0A=17、D1A=18。

查询同时检查对应原始 BIN 中每个动画块/程序号是否真的存在，返回 `program_present` 与 `all_programs_present`。存在只代表素材可解析，不代表该单位在游戏中一定会施放这个技能。
例如 A0A 的 action 13 程序存在，但当前动画导出器因该方向没有可见图层而没有导出映射；`program_present=true` 与顶层 `no_exported_direction` 可以同时成立。

C0A 等常规单位的 action 31 八方向指向 **block 1 的动画 6～10**，不是 block 0 的 151～155。D0A/D1A 共用动作表，但换用另一程序表，action 31 指向 **block 0 的 101～105**。对原始 BIN 的程序块数量检查也与此吻合：C0A block 1 有 31 条程序，D0A block 1 仅 1 条但 block 0 有 121 条。不过 E0A 的 block 1 只有 1 条程序，不能播放表中 action 31 对应的 6～10；查表结果不能单独证明动作可用。当前 `unit_sprites.json` 保留原有 `anims` block 0 数组，并在 `anim_blocks["1"]` 中按原版编号导出 action 31 所需的 block 1 时间线；Godot 解析器也按动作映射选择相应块。

## 技能 22 演示资源档

`python tools/skill22_unit_audit.py` 扫描十档原始 BIN，对 action 13/31/16 的八方向逐一查表和解释时间线，并计算可见画面变化数及源 BMP 的非透明像素平均亮度（0～255）。亮度只用于筛除过暗或空白的演示素材，不能证明原版调色板换色规则已经完整复原。

黄金演示档选 **C1A（运行时类型 14）**：北向 action 13 为 block 0/#61、1 个可见画面、平均亮度 85.9；action 31 为 block 1/#6、11 个不同可见画面、亮度 53.5；action 16 为 block 0/#76、6 个不同可见画面、亮度 83.6。三个动作全部八方向可解释，镜像标志与原版表一致，三阶段亮度均不低于 50。C0A 的恢复动作只有一个画面；E0A/E1A 的 action 31 原始程序缺失。以上是资源适用性筛选，不等于已证明 C1A 对应角色在原版可学习技能 22。

## 技能 22 的 EFCT 原始时间线

`EFCT.BIN` 的全局 2044 = block 1/#44，97 tick、25 步、从第 13 步循环，最大两层；3027 = block 2/#27，36 tick、10 步、不循环，最大两层；2029 = block 1/#29，19 tick、7 步、不循环，单层。三条时间线引用的 86 个去重依赖帧均已导出。这里只能证明资源与时间线，不能由此断言 3027 是飞行投射物、外部线性位移还是定点释放。

## 3027 释放消费者与坐标结论

原版 `UnitCtrlAi.cpp` 的 `0x477980` 在技能施放状态读取 `0x611538 + skill_id*0x10`：施法阶段把 `row+4` 的 2044 放入特效槽 1；进入释放阶段时先以 `0x46BCC0` 选择单位释放动作，再用 `0x46BEB0(unit, row+6, 0, 0, slot=0, metadata)` 启动 3027。该调用把目标编号等 12 字节元数据复制到槽 0 的 `+0x48..+0x50`（单位对象 `+0xE8..+0xF0`），但**传入目标元数据不等于产生目标方向位移**。

`0x465140` 将 3027 解为 block 2/#27；`0x40AF40` 生成动画节点时，根节点使用单位特效槽，位置只加调用者传入的零偏移。绘制时 `0x46CBD0 → 0x40A290 → 0x40B0F0` 把单位当前屏幕坐标作为图层基点。故已证实的锚点是**施法者**，不是目标格。若单位本身位置改变，基点会随之改变；这与特效独立沿源目标轨迹移动不同。

原始 block 2/#27 程序依次为音效、可见帧、一次 block 3/#16 子动画（偏移 `0,-40`）、四次可见帧及终止空白帧；子动画没有额外路径参数。离线逐帧展开后，10 步共 36 tick，全部可见图层的局部坐标均为 `(0,-40)`，第 9 步是 6 tick 空白，且无循环。所有可见指令的 `0x04/0x08` 事件标志均未设置；`0x40A520` 只有在这些标志存在时才把节点携带的 12 字节元数据送入事件队列。因此 3027 自身没有可见的目标追踪或事件驱动位移。黄金断言见 `tools/tests/test_anim_exports.py`。

结束条件有两条独立时钟：3027 的 DxAnim 在终止空白帧结束后自然停止；`0x477980` 的释放状态 `case 0x16` 则检查单位动作完成标志 `unit+4`，随后切入表中恢复动作。原版**没有**以 3027 的 36 tick 直接决定释放状态结束。当前 Godot 通用技能阶段仍以特效时长设置 release duration；接入技能 22 时必须另核对 action 31 的动作完成时刻，不能把两条时钟合并当成原版已证实行为。

结论边界：已查到的 3027 生成、时间轴、事件标志和绘制链均不支持独立的线性、追踪或抛物线移动；因此本轮不定义 `path_mode`。未做原版进程逐帧抓屏，不能进一步断言其它战场条件下单位自身绝不移动。

## 玩法效果 6：已固定的入口，尚未完成的语义

`0x48B2E0 case 6 → 0x48BBE0 → 0x48B720/0x48C850` 明确将攻击表的 `hit_effect=6` 走独立路径。`0x48BBE0` 构造 16 字节状态参数，`+4` 写技能号，`+8` 写 `0x48B720` 算出的主值。`0x48C850` 先经 `0x4828A0` 用目标快照修正或取消该值，再进入 `0x490180(target, kind=0, condition=6, params)`；回调表 `0x618FB8[6]` 指向 `0x48F330`，后者把类型 6、技能号、`+8` 主值和 `+0xE` 辅值写入目标的 `+0x14` 条件槽。它还启动另一独立视觉 ID 并记录条件事件，故不能把玩法效果 6 等同于 EFCT 3027。

条件表 `0x6F4088[6]` 的原始 16 字节为 `06 00 01 02 02 01 00 2E 2F 00 00 00 00 00 00 00`。周期回调表 `0x6190D0[6] → 0x4904A0`，每 tick 递增条件槽 `+0xC` 计数，超过 179 时归零；`0x490A50` 对条件槽 `+8` 的非零值每 tick 减一，归零时调用 `0x4902E0` 清槽。因此 `+8` 是条件剩余 tick 数，不能当作即时伤害。

效果 6 的入口还分两道门：`0x488BC0` 只有在基础攻击判定成功后才调用 `0x48B2E0`；进入效果回调后，`0x48C850 → 0x4828A0` 按条件表字节 `+3` 选择目标快照字段。效果 6 的该字节为 2，故读取 `0x4DE930` 快照 `+0x0A`（目标 `wk+0x50` magic）；字节 `+0x14` 为 0，`0x4DFBA0` 对目标职业索引查 `0x6B2DAA + job*0x40`，三十个职业该值全为 0。`0x4828A0` 算 `clamp(100 - target_magic + job_modifier, ≤100)`，并按此百分比缩放 `+8` 时长；效果 6 字节 `+5=1` 使本分支不按随机数拒绝，而是时长缩放后要求结果严格大于 `0xB7`（183），否则清零并拒绝应用。它每次仍调用随机函数，但该表标志下随机值不参与此判断。

技能 22 的 `0x6D4E58+22*7` 属性行为 `01 01 01 03 01 01 02`；字节 `+3=3` 令 `0x48B720` 选择施法者 `wk+6`（AGI），按 `3600 + AGI*1000/100` 得到基础时长。例：AGI=30 时基础 3900；目标 magic=95 时缩放后 195 ticks，可应用；magic=96 时为 156 ticks，低于 184 阈值而拒绝。效果值写在状态槽，不是 HP 伤害。

`0x46C9F0(skill_id)` 只有 skill ID 大于 100 才返回真；`0x48C850` 仅在此条件成立时才额外比较施法者 `wk+0x41` 与 `rand()%100`。因此技能 22（22≤100）不走该概率分支。同分派条目 537 的 attack row `power_base/scale=0`，但 ID 大于 100 且使用 `0x738AF0` 的默认技能属性行（`01 01 01 01 01 01 00`），会走额外概率分支；其基础效果值从施法者 `wk+0x48` 取得。此交叉项说明效果值源和概率门取决于技能 ID/属性行，不能把技能 22 公式泛化到所有效果 6 调用。

覆盖时，`0x48FF70` 拒绝与现有类型 46/47 冲突的应用；`0x48FE50` 比较旧、新条件的优先级。类型 6 的优先级字节 `+3=2`，写入时 `0x490180 → 0x4902E0 → 0x48F330` 清理选中槽并写类型 6、技能 ID、剩余 ticks、辅助值。`0x48F330` 还启动独立状态视觉。仍未闭合的是类型 6 的周期计数 `+0xC` 怎样触发持续 MP 扣减，以及该状态在 MP 到 0 时如何处理；技能说明文本虽描述精神枷锁与持续降 MP，但尚未证明其文本索引与技能 22 的运行时行一一对应。因此**本轮仍不标记任务 1.1 完成，也不实现猜测性的 MP drain**。黄金表字节和职业抗性表检查由 `tools/tests/test_skill22_effect6_evidence.py` 固定。

交叉表项：攻击 22 的 `hit_effect=6`、`power_base=3600`、`power_scale=1000`、`target_filter=2`；同分派的攻击 537 也是 `hit_effect=6`，但主值基数与系数均为 0，`target_filter=1`，不能把技能 22 的持续值硬编码成效果 6 的通用常量。`0x6D4E58[22]` 的原始七字节 `01 01 01 03 01 01 02`，`0x48B720` 用第 4 字节选择施法者 `c_agi`，按 `3600 + AGI*1000/100` 计算初始值；目标修正后可能缩短或清零。以上地址、表项和回调指针由 `tools/tests/test_skill22_effect6_evidence.py` 锁定。
