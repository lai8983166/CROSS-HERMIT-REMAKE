# 原版角色图层的名字体入口

本轮从原版确认等待之后的 `4C61C0` 自然入口续跑。脚本 PC252 的
opcode30 参数为 `[8,4,0,30]`；8 是配置索引，配置行的实际图层为5。
配置包含位置254/368、文字起点308/400、姓名位置855/529和样式5。
来源目录保留19个原始有符号WORD、编码参数、角色名原始Big5字节、字体请求及关键指令。

原版先执行 `4CC600` 图层初始化，再进入 `4CC0F0` 初始化该图层的文字对象。
后者调用 `4CA770`，在角色图像加载之前请求高度20、字重700的名字体。
这是独立于前两行对白的资源路径。图像表解析得到 `data\adv\bin\sc004.bin`，
对应图层资源槽32/33；这只是后继加载依赖，不能视为已读取或显示该图像。

`tools/school_character_prefix_catalog.py` 从固定原版镜像和脚本推导完整前缀：
参数区、图层WORD字段、文字对象初始化、四层调用帧和14个字体参数。
旧图层必须保持原始未使用状态，其他状态直接拒绝；不拿执行后的字节生成预期值。
`tools/school_character_prefix_emulation.py` 继承已验证的确认路径，保持原版CPU和
两个真实纹理存活，继续运行到 `CreateFontA` 入口，返回地址为 `4CA7CB`。
仅允许来源已证明的字段和栈写入，并比较全部八个内存区域及其他映射字节。
前两张纹理逐字节读回，仍由原有资源所有者负责释放。

本轮不会把新名字体的创建、姓名光栅/纹理、角色图像读取、图层动画、第三句对白、
GPU绘制或世界调度记作已执行。下一步应复用真实GDI平台适配器补名字体及纹理，
再追踪 `4CBF90 → 4CDE10` 的实际图像加载，最后接图层动画等待与第三句对白。
Godot现有地图和十段对白预览、存档及冒险就绪门槛保持原样。

验收：三案例通过，Python36模块136项、严格规格30项通过；661个历史文件与10项存档规则指纹保持不变。权威来源/比较导出使用`school-character-source-v2-20261013.json`与`school-character-comparison-v2-20261013.json`（UTF-8）；初版控制台GBK输出保留为历史记录。原生执行证据v1始终为UTF-8，未改写。
