# 原版纹理依赖与32位平台核对（2026-10-12）

原4136D0以SDK220调用Direct3DCreate8，工厂存在renderer+B20C；413730按(type1,flags44)、(1,24)、(2,44)、(2,24)尝试设备。窗口/全屏初始化通过工厂vtable+3C写renderer+B210，4139E8等将原flags加入4。当前保留CPU中该设备字段为0，尚未执行这些初始化；GDI的离屏测量DC不能替代Direct3D设备。

原403BD0先检查纹理元数据，再释放旧资源、将两个维度分别用403B70取2的幂。文字元数据174×24实际请求256×32、levels1、usage0、format25、pool1和真实输出槽texture+2C。随后在403C81解引用设备，403C87调用device vtable+50，成功后通过texture vtable+38取得level0描述。

三组已捕获文字元数据在另行声明的CPU记录上执行，原尺寸函数、七项预备参数和完整记录保持全部核对。设备0停在403C81第一条解引用前，无虚构vtable、HRESULT或纹理。零宽/零高/零format按原版返回1，没有COM调用。403B70使用signed WORD比较；输入16385及以上需要32768或更大结果，WORD移位回绕导致不能正常终止，工具明确拒绝，不用现代取整结果覆盖它。

这些是隔离的来源依赖核对，不是已经释放GDI资源的自然栈继续，也不证明原GPU、VM或对白已完成。真实主机纹理平台将另外验证，原renderer设备0保持原值。

## 真实32位纹理平台

独立x86 .NET辅助进程直接加载本机Direct3D8，以SDK220取得实际工厂/设备/纹理指针。程序用隐藏的窗口模式测试，不调用ShowWindow、Present或绘图，也不修改系统分辨率。原版设备尝试顺序用于这个明确声明的平台输入；三例均以type1/flags44成功，HRESULT均0。它与原renderer初始化保持分开，不把平台测试指针写进原CPU。

实际请求256×32、levels1、usage0、format25、pool1；GetLevelDesc完全吻合，实际LockRect行距512。输入是三例真实字形经原405A80转换后的174×24像素，分配矩形剩余区域明确填零，并逐字节与独立转换再次比较。整张纹理16384字节经写入、解锁、只读锁定和读回全部一致，不只抽样有效字形。测试另验证4×2颜色/透明图案。

编译源、编译器、x86 PE machine和实际加载DLL的SHA256单列。32位进程显示逻辑SYSTEM32路径，物理SysWOW64文件身份另核对，不能用64位进程的System32视图代替。实际资源指针仅是此次进程记录，捕获后全部释放；三例texture/device/factory的Release返回均0，隐藏窗口销毁成功，不可复用这些指针。

非法尺寸、非二次幂、缓冲区长度错误和既存输出文件在平台调用前拒绝；写入权限仅限审计输出。验收校验完整像素、HRESULT、接口顺序/参数、实际行距、资源释放和未修改原renderer/VM的边界。[平台记录](../analysis/school-d3d8-platform-v1-20261012.json)与[来源记录](../analysis/school-texture-contract-v1-20261012.json)分开保留。成功证明此主机可以提供真实资源；原自然设备0、403BD0后续、文字对象完成和事件/波次仍待接入。
