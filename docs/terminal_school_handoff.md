# 原职务室、学校及战斗的自动交接

本轮延续 `connect-terminal-wait-and-battle-exit`。原菜单 v6 已观察到178次自动剧情确认后职务室唯一注册；本轮仅增加当前输入和后续观察层，不改写固定父来源。正式验收继续要求两个新鲜来源、独立完整重放、完整 CPU/内存/权限/ABI/累计轨迹以及原生资源寿命，任务仍为2/8。

## 自动化边界

`devtools/terminal_school_handoff.py` 从原程序启动开始，一个隔离 Job 中只运行一个实例。当前版本只允许标题新游戏、职务室退出、学校出发与确认、开场通知确认、战斗退却与确认七个原鼠标操作；三段原剧情确认预算分别为192、192和64。所有输入均先验证当前注册图、窗口/PID/Job/前台、当前线程/TLS、原代码、真实 cursor API 出口及原始游戏坐标。鼠标只在被审查目标精确命中后按下，所有按键有释放路径；没有调用宿主游戏根、写输入/结果字段或强杀原 worker。

输入失败不重试，未覆盖状态不补写，连续60秒无语义进展保存停点，单次原生寿命上限1800秒。原生运行期间冻结全部输入/采集层。资产哈希检查是单独前置工作，不计入原生寿命；压缩证据上限24 MiB，原始 JSON 只在有界内存中生成，不持久化大快照或复制父历史。

- 职务室只在原 `49FF57 → 4A15D0` 选择等待、对象 state1、唯一工作节点和正确 selector 栈时点击 `(917,741)`；等待原 worker 自然退休。

- 原任务模板、日期筛选、账本注册和出发分支由 `terminal_school_preparation_contract.py` 验证。其原指令模拟使用声明的合成账本，只作静态分支合同，不冒充本轮真实学校准备。
- `terminal_story_catalog.py` 从固定父资产清单读取原字节，并将实时 VM 代码范围的长度和 SHA-256 与原 ADV/Tactics 数据匹配；不再单凭代码长度命名剧情。相同字节资产保留全部候选，不强行认定唯一文件。

退却是单独声明的当前操作案例，不替代旧中立/超时案例。即使观察到原结果局部、尾等待、worker退出0和后继菜单，也不直接声明完整等待 API 返回、资源/PTD清理或完整战斗退出。

## 验证方式

独立 `terminal_school_handoff_verification.py` 不导入采集器或原生输入实现。它复用固定父验证器，并独立解释新原字段、输入边沿、几何反馈、当前线程/TLS、完整任务图、代码资产匹配与退出观察；采集时的布尔声明不是通过依据。失败来源只能作为失败证据，不能包装成成功证明。
