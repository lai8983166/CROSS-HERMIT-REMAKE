# 原版角色姓名的真实光栅与纹理

从前轮 `4CA770` 的自然名字体请求继续。该路径请求高度20、字重700，
按原版姓名表取索引4的Big5字节，使用现有真实Windows GDI平台进行字体创建、
测量、DIB生成、阴影和前景绘制。宿主ANSI代码页及实际选中字体单独记录；
这些像素不证明已复现原安装环境的字体显示。

姓名不是对白行：其纹理在第5号图层节点的 `+0x60`，字体句柄在 `+0x5C`。
新增执行器使用独立光栅 `0x3A000000`、锁定镜像 `0x3B000000`，
保持前两张对白纹理存活。原版 `403BD0/403910/405A80/403990` 完成第三张
真实纹理的创建、锁定、像素转换和解锁，原版后续负责位图、绘图DC和名字体清理。名字体资源释放后，原版保留节点中旧句柄的数值；这个数值不能当作仍存活的字体资源。
它不会增加对白对象的行数，也不会推进VM的PC；这时仍在opcode30内部。

原版接着设置图层尺寸736/214、资源编号4、场景资源表行 `0x622758`，
执行目录复制和文件名拼接，形成 `data\adv\bin\sc004.bin`。
拼接使用严格核对来源、目标和返回地址的有界CRT适配器，目录复制函数体实际执行。
在 `4CDE10` 的第一条指令之前停止，资源槽为32。原目录复制循环通过 `xor edx, edx` 清零寄存器，
所以入口的完整DWORD参数也为32；此前仅按资源表地址推测上半字的规则已纠正。
文件读取、图像解码、图层动画、第三句对白以及GPU绘图/Present均是后续工作。

独立校验器核对所有23次GDI调用的顺序、参数和返回位置，完整光栅几何/哈希，
自然调用栈、八个完整内存区域、原版四次COM调用、转换矩形、完整锁定缓冲和纹理读回。
每个阶段比较前两张旧纹理，并核对有限写入之外的映射字节。
全部三张纹理、设备、工厂、窗口与剩余三个测量DC必须清理。

继承父阶段校验时，校验器从实际完整清理结果中选择两张旧纹理，并以父阶段的
两个测量DC进行验证投影；原生证据仍保存完整的三资源结果，从未改写为父阶段结果。
投影前先独立核对实际完整清理，避免把旧阶段校验当作第三张资源的证明。

第一版光栅运行在栈校验处失败，原失败日志保留。重新解码原版函数序言确认姓名
局部栈分配328字节、对白336字节，因此姓名到光栅帧为468字节、到纹理入口SP为728字节。
权威来源规则v5取代早期v1的栈距离、v2尚未核实的资源参数上半字及v3误清空已删除字体句柄的规则；新原生记录使用独立路径，未覆盖旧证据。
