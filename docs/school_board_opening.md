# 首次对白面板开启与就绪来源（2026-10-12）

本阶段沿保留的原版 CPU 调用栈执行首次面板开启，再执行面板动画与就绪检查，到下一条对白激活指令的函数入口。它是原版逻辑验证，尚未接入 Godot 图形对白。

## 原版执行范围

`tools/school_board_opening_emulation.py` 在三组原版学校编班 CPU 检查点上，完整重现摆放、部署、初始化开场、入口控制、脚本预检查/绑定和正常开场六个父阶段，并要求完整结果等于各自不可变报告。检查点哈希、父报告身份和继承拒绝证据单列；没有重新执行全部更早的资源加载链。

自然 `4C5EA0(0, script+660, 1)` 对应 T0005 的 opcode27。参数是面板4和两个立即数 `0x0FFFFFFF`，原版暂存字段保留完整32位值。EXE `624520 + 4*38` 的配置把面板4映射到层7，而不是直接映射到层4。原版配置启用层、写入位置和正文矩形、帧样式1和背景样式0，并设置空文字对象的24/12尺寸。背景模式1不需要加载字体。

`4CA1B0`、`4C99E0` 和 `4CD4D0` 对活动层实际执行。`4CD850` 原版整数插值与 `4CA600` 四片边框分解也实际执行。只有底层 `4CBDB0` 精灵绘制和 `410310` 矩形绘制，以及父阶段已有的未激活绘制接口，被作为严格调用者/参数约束的终端接口记录。不能把整个活动层更新替换为无操作，否则动画不会前进。

开启动画限值45，使用旧计数计算透明度，然后增加计数；增加后的值大于45才改为就绪模式2。因此第46次动画绘制后模式变为2，而 VM 等待仍为1。下一次原版 `4CD060` 检查观察到就绪，再清除 VM 等待。总计47次完整 VM 返回，下一次自然进入 `4C4DC0(0, script+676, 0)`，尚未执行对白激活首条指令。

## 独立核对

`tools/school_board_opening_catalog.py` 单独校验 EXE 身份并解码关键原指令、T0005 指令、面板配置和四片边框表。模型从输入内存重建完整八个区域、47次更新、46次就绪检查和每例2538个终端接口参数的哈希，未把原版输出作为预期值。

原版16位 `mov` 保留32位寄存器高位：精灵透明度栈参数保留边框表指针高位；最后稳定态矩形资源参数保留 `0xFFFF` 高字。这些原始栈字节与用于绘图的低位含义分别核对，不清理原版高位。所有非所属映射内存和地址0字节保持原值。

来源规则与原版证据分别输出到 `prototype/data/school_board_opening_rules.json` 和 `school_board_opening_evidence.json`，不作为运行时 fixture。

## 后续边界

此阶段执行了面板开启、动画和真实就绪谓词，未执行文字激活、文字排版、字体/GPU、波次、完整任务包装器的音频门控或世界调度，也没有现场画面见证。下一步从保留的自然 `4C4DC0` 调用接对白，然后推进实际事件/波次和图形战斗。
