## 本轮实际实现

`prototype/sim/tactics_result_consumer.gd` 还原453CB0至453CDD的控制顺序：

```text
保存本轮完成值（原[EBP-8]，不等于胜负selector）
发起第一次yield(0)
收到对应的成功恢复后，首次读取完成值
    为0：继续下一轮，不发退出/回放/奖励事件
    非0：请求4967B0对应的可选回放结束记录调用
调用返回（EAX不参与完成判定）
第二次yield(0) → 恢复 → 第三次yield(0) → 恢复 → 返回固定1
```

每次恢复必须匹配迭代号和等待序号。重复、过期、乱序及失败等待不会推进状态。
这是Godot领域逻辑，恢复事件由调用方显式提供，不是Windows线程或事件证明，
不把三个调度边界写死成三帧或固定毫秒数。原代码没有检查Wait返回值；当前适配
只接受成功事件完成（status0），属于明确的输入合同，不声称逐指令复刻失败路径。

输入必须是调用方已产生的完成值。453F10返回只是正常模式的一项来源，4539B0的
其它分支也可能置完成值；不能把任意动画返回或胜负类型直接接入。输入保留32位值，
仅按零/非零分支，输出不生成winner、奖励、学校进度或存档权限。

`TacticsResultTransition.after_waits()` 将该状态接到既有场景5分派**预测**。
它要求三次恢复结束，仍保留旧场景/联机/已有请求等限制，不执行原451670的十轮
尾等待、465E60清理或完成门，也不向真实控制器发出请求。原`step()`行为保持不变。
该场景5投影仍不执行真实分派；学校战斗试验的返回入口不使用这份投影。

流程为：作战 → 本地结束判定 → 首次恢复/读取完成值 → 可选回放调用边界 →
第二/第三次恢复 → 结果页 → 一次性交接与临时资源引用清理。

初始敌人全清、当前学生全倒、玩家主动结束是当前试验规则；其中全清不是原冒险通关，
主动结束不是推断的原版退却selector。完成值1由重制会话产生，状态机接受的恢复事件
也由Godot显式发出；不冒充Windows等待或新原生现场。每次调度只处理一个消费动作，
结束期间冻结攻击/移动；暂停时仍能结束。回放未启用，不写伪记录。

结果页显示初始敌人及当前学生统计，必须明确返回后才关闭。交接仅恢复原学校准备页，
不授奖、不改日期/冒险门/编班/存档；正式开始战斗入口保持原有限制。关闭后清除会话、
地图/精灵引用、拖拽及名单，重复返回不重复发交接，重开重建初始队伍。
