# 正常开场脚本、渐入与对白面板入口

本轮从三组固定的真实 CPU 检查点完整重现五个父阶段，并逐项等于不可变报告。继续已激活、PC 为 0 的子段 0/1，显式调用原版 `4CE8F0` 和 `497AA0`：共完成 107 次 VM／渐入更新；下一次 VM 调用沿自然栈停在首个 `4C5EA0` 面板开启函数的第一条指令前。两组拒绝沿用父证据，没有重新执行全部上游或拒绝路径。

正常分支读到工作标志 1，相等比较为真，因此跳过预检查请求与 END。随后原版设置变量、全局字/位标志、组 1/2 字段，发出 60 计数渐入请求。`497AA0` 实际执行每次递增与递减，计数归零后原指令清除 VM 工作等待；没有人为调用完成回调。浮点转整数得到增量 648，60 次之后值为 38880，原版以计数归零结束，没有强制改成上限 38912。

之后原版设置演出模式、执行 30 计数延时：旧计数 30 才解除等待，因此需要 31 次检查。第 108 次 VM 调用进入文件偏移 660 的 opcode27，实际调用 `4C5EA0`，receiver 为 VM，参数为 `0 / script+660 / 1`，返回地址 `4CED48`。第一条面板函数指令尚未执行。此时 PC 208、等待为 0，任务阶段仍为 5、控制器仍为 7、171 完成标志仍为 0。

记录八个完整内存区域、全部更新状态和 14 条指令（含待处理 opcode27），对 5564 个绘制接口调用按顺序记录完整参数并生成逐次及总哈希。绘制接口只允许当前未激活的层、对象、资源和演出遮罩，不返回伪造的就绪状态。覆盖层的两个位置参数使用 16 位 `mov` 后保留了寄存器高位；报告核对实际 32 位栈参数，没有擅自清高位。

有限写保护只允许 VM、两个组的确切字节/字字段、渐入区、两个全局标志字段、指令计数及栈；任务、控制器、其他工作字段、单位、资源和其他映射内存保留。全量捕获较大的工作区与全局标志区用于核对原版没有写的字节。
