# 第三句真实文字、第五张纹理与自然等待

本阶段从上一轮图层5 text2 的自然 `CreateFontA` 入口继续。三个实际编班案例完整重放八个前置阶段和已核对的两句文字、姓名、角色图像、动画与第三句文字前缀。所有原映像、脚本和父报告均有固定身份。

## 真实字体和纹理

复用原版 `4CABD0 → 405160` 字体/栅格函数，目标为图层5首记录的纹理结构。实际执行23个原始 GDI 导入调用，包含字体创建、离屏测量、DIB创建、底色与阴影/正文绘制；模拟 CRT 字节复制和测量上下文获取仍是精确声明的有限接口。测量结果与所选字体来自本机 Windows GDI，不能当作跨机器固定字体指标或自动修正 Big5/ANSI 兼容。

新的栅格/纹理锁镜像使用独立地址 `3E000000/3F000000`。原始纹理初始化、尺寸进位、四个实际 COM 调用、按带像素转换、解锁、字体/位图/DC清理及文字记录计数实际执行。第五张纹理独立于前两句、姓名与角色图像的四张旧纹理；旧纹理仍存活并完整读回核对。

独立规则逐字节比较八个程序区域、完整栅格和锁定表面、所有带的矩形/目标与转换输出、自然字体/纹理栈、23个 GDI 调用的导入槽/输入、COM虚表/方法/输入、描述符、资源计量和清理顺序。完成第三句处理器后 PC286/wait0，文字计数1，mode2经首次更新转 mode3，fade count仍为0。此次只绘制旧两句文字，第三句从下一次更新开始淡入。

## 无跳过的原版淡入和 readiness

上一阶段的确认鼠标脉冲仍在隔离任务输入内存中。新阶段只把已声明的 `TASK+1990` 从1清零，记录三项鼠标输入 `[0,1,0] → [0,0,0]`，保持位置与空格键为0；这不是实时鼠标采集。输入重置发生在独立阶段入口，后续原版函数不得写入该输入词。

原 VM 下一次更新执行 opcode50，PC290/wait1，并绘制第三句首个淡入帧。随后执行原始全十对象 `4CB5F0` readiness 检查及鼠标/键盘查询，不调用文字跳过处理。两组文字对象都按 `4CB220` 更新，角色背景、框和姓名稳态呈现保持。

| 无输入更新索引 | 第三句状态与等待 |
|---|---|
| 0 | 开始 opcode50，fade count1，等待1 |
| 1–23 | 原始 readiness 尚未就绪，逐次淡入 |
| 24 | fade递增超过24，饱和到24并转 mode1；本次先检查旧 mode3，等待仍为1 |
| 25 | readiness观察到 mode1，自然解除等待 |

共26次更新、250次对象 readiness 和50次原始输入查询。最终PC290/wait0/opcode50，后继 opcode51确认尚未开始。五张真实纹理全部保持，外层释放五个 COM 纹理和四个保留的测量 DC，辅助进程退出；清理投影只用于核对父阶段，不覆盖完整实际清理报告。
