# 原生场景自动化与资源失效诊断

2026-11-07。属于 `connect-terminal-wait-and-battle-exit` 的开发前置，不是新的功能验收。任务仍为2/8；R3–R6、完整战斗退出、原等待返回与结果消费均未完成。

## 本轮实际边界

- 自动输入已由 Agent 执行。复用用户2026-10-22明确授权的私有窗口扫描码后备输入，绑定当前 Job、PID、HWND、前台及桌面，不写游戏输入、结果、代码、IAT或寄存器。实际历史授权已在原聊天核对，不要求用户再手动操作。
- 自动 v4 在真实 T0004 第一处确认PC154等待后，原输入查询观察到 `0,0,0,1,1,0`；第一处进展即松键，实际单调时钟持键47ms，最后停在PC172。原函数 `4128F0` 用完整0xA00输入对象独立重放并检查只读/ret8 ABI。这只证明一次真实确认及有界观察，不证明逐指令输入因果、资源正常寿命或战斗退出。
- 当前入口已经拒绝有旧任务的叠加构造：三个原初始化/场景事件根以及自动输入都不会执行。即使任务图、渲染队列、group90恰好为空，也不能把可能处于注销与析构之间的快照当作自然交接证明；在原退役祖先和原子交接尚未接通前保持拒绝。
- **资源失效尚不能宣告修复。** 已修复的是测试入口继续执行已知不合法构造的问题。自然场景切换和资源释放的完整因果仍需接通；拒绝测试成功不是游戏流程成功。

## 旧故障与构造缺陷

旧 owner-v4 在第135个样本首次出现同一故障，后续123个故障样本不是123次独立崩溃。实际D3D8指令在 `base+4D8E8` 对 `EDI+10` 访问，EDI为DDDDDD8D；按实际模块原指令反推资源参数为DDDDDDDD。设备指针与原GAME的renderer设备字段一致；不是仅凭错误窗口推断驱动问题。进程死亡后的对象读取/窗口关闭错误是次生错误。

更关键的证据是原注册图：样本133移除startup，134新增菜单59B060，135发生资源访问异常，而battle59A430始终仍在图中。菜单45EC5F和场景451B10都使用资源组90；41F0E0重新加载组时先经41F4E0释放旧描述符数组。当前旧三根仅发布场景事件16，MAIN分派不会自动退出旧worker。用户点击可能被仍活着的startup消费，产生菜单任务与battle并存；具体故障descriptor地址未被旧采集覆盖，因此“哪一个描述符被哪次释放”仍不是已证明事实。

清文本4C4EB0→4CADE0只复位计数，不直接释放纹理。描述符数组步长0x54、数组cookie在base−4、CRT头在base−0x24；不能把任意descriptor−0x20当作分配头。新资源观察器保留原renderer调用参数、队列节点、描述符和候选CRT头，限制每样本4096B/96次读取/6个队列节点，不复制纹理像素或遍历全堆。

不能用422090强制注销当作正常退出：它实际调用TerminateThread。422560(node,2)虽然能屏蔽原调度，也不能证明旧worker自然释放或资源寿命修复，本轮没有采用该绕行执行器。

## 自动化接口与剩余阻断

新startup-only探针完全不调用三个场景根，保留100秒原启动过程。Computer Use可识别精确私有进程窗口，但可访问树只有window0，点击返回`coordinate input geometry is unavailable`，启动画面截图返回`FrameArrived timed out: timed out waiting on channel`。这次未交给用户操作，也未盲点坐标或写鼠标字段。测试私有进程已结束。

原startup自然尾通过鼠标状态或原动画推进后发布event1并返回；原菜单新游戏发布event7进入真实剧情链，事件16应由剧情当前排程选出场景后发布。T0004不能直接叠加到存活菜单上；地图菜单的场景表也没有4。下一步应建立可自动操作的原启动/剧情或原读档交接，再复用等待体、结果消费及完整退出证明。没有接通前不重跑小时级终局前缀。

后续有界观察已覆盖原动画自动终点：约273秒计数16205、状态100后，startup原线程退出码0，旧节点消失，菜单成为唯一任务；该段全程无需人工输入。详见[无人工输入的原启动交接](terminal_startup_handoff.md)。这推进了startup→menu前置，但菜单→剧情/读档→battle仍未接通，旧资源失效的完整寿命结论保持未完成。
