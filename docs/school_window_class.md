## 同一原 CPU 执行了什么

每组都从第一条 `49DDC9` 指令前声明真实自有资源模块，在同一 CPU/助手寿命内重跑完整主对象分配、构造、发布、任务槽、实际重复窗口查询、矩形和图标/光标/库存画刷，随后继续注册。第一条 WinMain 中段之前的入口/CRT 仍未执行。

注册导入的审计陷阱仅在 `45047D` 前加入，加入前后 CPU、完整 owner/保护区、映像、栈和空页保持；原 IAT 未改。原调用压入真实返回地址，真实接口的 EAX 位值经已释放的 19 字节自有转发器捕获后返回原 CPU。原 `and eax,FFFFh` 再检查实际 ATOM，未预设成功或替换原调用者分支。

原始动态 HINSTANCE 全程保留。继承验证器仍通过公开的 31 项输入派生值校验副本核对原前缀；新类注册与后续节点直接验证原始实际值，原始轨迹没有因验证而改写。

## 类记录如何交给真实 Windows

原 48 字节 WNDCLASSEXA 保持 `lpfnWndProc=424980`、`lpszClassName=7A2628`。这两个值属于模拟中的原程序。助手只在自有宿主副本中转换两个字段，并记录完整原缓冲、宿主缓冲和转换清单：

| 字段偏移 | 原值 | 宿主副本 |
| --- | --- | --- |
| `+8` 回调 | `424980` | 自有、保持存活的 stdcall IPC 回调地址 |
| `+40` 类名 | `7A2628` | 带保护区的 `Cross Hermit\0` ANSI 缓冲 |

其余十项字段保持真实模块、原始样式、实际共享图标/光标/库存画刷和零菜单等完整值。注册前查询实际缺席，注册后分别按实际原子和精确名称查询。按原子查询返回的类名字段实际为原子值；按名称查询返回名称指针。验证器逐一核对两种形式、解析后的名称及其余全部字段，不把原子当作可读字符串地址。

此回调目前只具备请求与原版结果返回的传输边界；创建窗口所需的嵌套接口服务和原版回调 CPU 尚未接入。助手没有窗口创建操作；若注册期间意外收到回调，审计端拒绝继续，不供应固定返回值或代用游戏处理函数。记录中的回调次数均为零，因此这里只证明传输地址的注册与寿命。

根据微软的接口约定，成功注册返回类原子，真实类信息可以按原子或名称查询，DLL 卸载前需要明确注销其类。见 [RegisterClassExA](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerclassexa)、[GetClassInfoExA](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclassinfoexa) 和 [UnregisterClassA](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-unregisterclassa)。
