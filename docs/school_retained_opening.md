## 原执行边界

六分支每例均为222次完整 request → 两队列复位 → task，共888个任务区间，加4个原键盘处理片段，共892个前进区间。新增原指令11,627,289条、原写入6,115,840次，业务边界194个映射。每个task均自然返回，最后实际执行 opcode19及原4CE090/4CE800调用，VM+4/+5两个通道活动字节从01/01变为00/00，PC保留492、wait0。496是脚本代码范围末端，不能当作原执行后的PC。

独立重放逐区间核对全部映射的完整SHA256。为避免重复读取约117MiB未改动内存，摘要缓存从独立原执行后的全字节读入建立；原CPU每次写入、平台全部内存输出、声明的根栈和捕获输入写入都标记变动，新增/合并映射重新读取。业务终止、六个字形析构完成、旧资源清理完成及原CRT收尾另外做新鲜全字节重读。原指令字节、完整CPU、全部队列和API核对不减少。

`--jobs 3`按三个分支各自的76/77组合启动三个独立验证进程，复用各自只读来源缓存；默认单进程也可复现。并行模式只将三种GPU证明助手的构建文件名按PID隔离，原助手源代码、原指令执行、API核对与原生对象所有权规则不变；每个证明仍新建自己的原生对象并正常关闭。

确认分别发生于PC366和416。每组先执行两次无输入控制，再绑定已验场景捕获的256字节原始键盘设备数据，经原4113d5–4116a4处理片段计算派生字段，随后由原完整task消费；松开也运行同一原片段。没有OS键盘注入，没有宿主写入PC/wait、派生键盘状态或动画计数。
