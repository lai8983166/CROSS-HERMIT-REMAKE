# 原版渲染器初始化前提实验

日期：2026-10-17。此研究使用独立的原版机器码实验环境，不修改或推进 vm-graphics 的三个 owner_read 检查点；其终点仍为40E2D0、PC224/wait1。

288来源：原40D7E0/4107B0构造96字节管理器，仅清零指定字段，+18/+20设1，+8/+C/+28/+2C/+38/+3C并不由构造器写入。40D970把显式所属对象写入+0，经原4142B0读取owner+B210写入+4。原413450先写owner+B278/B27C尺寸，完成设备相关步骤后调用40D970，随后40DAB0分配4096×8图层表及1MiB命令区。内存来自428A40→56E810调试CRT分配，不能等同于真实D3D初始化。

原49E540顺序为输入重置425DE0、图层表清空40DB90、命令写指针/计数重置40DC80、任务处理4217C0，随后414C30、40E330、414DE0及条件调用4152C0；本轮仅静态绑定该外层顺序，没有执行完整外层帧。

矩形410310先以40E2A0读取所属对象尺寸并做带符号拒绝判断，调用原abs56DB00；相等边界允许，32位溢出及INT_MIN保留原语义。kind4从40DCD0获取24字节命令空间，再由40DF20插入对应图层链表头，写指针递增24并维护高水位。容量判断要求packet_end严格小于arena_end，正好剩24字节也会走调试边界，不能误写为允许。

六项来源/投影测试通过。后续实验将显式声明scratch owner/device/dimensions/gate和CRT分配响应，验证完整管理器/图层表/命令区与隔离写范围；这些都不是当前VM恢复、GPU出图或游戏进度的证据。
