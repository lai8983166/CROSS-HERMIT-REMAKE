## 来源与开放条件

## Godot接续与存档

`school_return_adventures.gd`提供`initial / available / select / prepare / submit`。选择冒险只填写源工作字段，不替玩家切换班级活动。提交前重新评级，按当前教师和实际槽位产生队伍；法娜可加入第四槽，待命者不混入队伍。交接保存当前参战成长、participants、源场景身份、state10→16请求及round_cursor1，不发奖励、不推进日期，也不声称已构造战斗单位或启动战场。

返校界面先选择“继续安排本周”，再选择授课/冒险、课程或任务。授课与出击均需明确确认，确认前可继续调整。授课显示四人的实际结果、技能和MVP，后续CH003尚待接入；出击显示已保存的任务与队伍，并明确战场尚未开放操作。提交后冻结同周计划，不允许重复结算或重新出击。

v6存档记录上述合法命令，从既有可信起点重放并核对完整状态摘要。旧v5在没有`return_plan`时保持原快照形状、规则指纹与版本；v1–v5继续可读。保存途中、课程结果和出击交接均支持恢复；重复提交、错序、外来奖励字段、错误规则身份和篡改摘要原子拒绝。

`tools/tests/test_school_return_adventures.py`实际执行原`4A17B0/4A1920/4A9D90`局部函数，核对完整表、上述时间线、期限、复用及不重复开放。班级评级是明确声明的局部边界；这不是原生线程或完整周场景见证。Godot测试另外验证四人/待命名单、8/17两种交接、成长保留、课程与冒险互斥、UI确认、存档往返及拒绝。
