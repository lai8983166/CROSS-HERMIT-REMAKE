## 本轮已接通的原链

沿固定父来源的三个初始根继续，不重采旧窗口：

```text
原 WinMain → 原 MAIN/窗口 → COM/音频/影片 → 413450
  → 全屏模式枚举与 CreateDevice → 字体 GDI/DIB/纹理缓存
  → 两套字体、四个状态块、顶点缓冲、队列、原 gamma 设置
  → 413560/410E90 → DirectInput8Create → 原键盘/鼠标初始化
  → 4506E9 原 GAME 发布 → 停在4506EB
```

`terminal_graphics_native.py/.inc` 和 `terminal_input_native.py/.inc` 继承冻结的
当前所有者。Reader/worker 不变；平台叶限同一 MAIN/TID/TEB、固定调用槽和原参数。
构建为 x86 Windows subsystem，`/W4 /WX /MT`，仅编译、未运行。
dispatch 在可能同步重入的平台调用期间释放锁，回调仍要求完整父请求/线程/TEB/
深度和 CPU57 恢复；模型中的20次回调不是实际图形或输入重入资格。

图形采用原全屏参数及真实模式枚举接口，没有复用旧工具的窗口模式替换当前工厂。
冷启动原 `52B019` 自行通过 GetModuleHandle/LoadLibrary/GetProcAddress 解析
DebugSetMute；没有套用旧快照的函数地址或给原全局强行补值。每个实际模块独立
计数，支持原代码的两对静音调用；加载引用与最终 COM 引用都保留真实待清理账本。

字体只处理本轮创建的内存 DC/DIB、纹理锁和原字符数据，不读取显示器像素。
像素按32KiB分块往返，保留每次 Lock 的新指针/步长及初始字节，解锁前校验上传读回；
只读锁拒绝写入。DeleteObject 成功而对象尚活时保留延期义务，只有后续 GDI flush
和失效普查确实命名该对象，才能清账。设备 gamma 在原设置前保存，最终设备 Release
前补充恢复并比较原1536字节，不能用 API 成功码替代读回。

输入保留原 WinMain HINSTANCE，不偷偷改为 helper 实例；原普通资源 DLL 必须通过
MEM_IMAGE、模块、PE 和 HWND HINSTANCE 核对。键盘256项、鼠标11项 dataformat 的
完整 header、对象表与 GUID 原字节在投影前核对；原 flags=6 不改成后台输入。
原 ClientToScreen/SetCursorPos、鼠标属性、设备信息和设置读数均有窄接口。
原析构先两次 Unacquire、释放两个设备及工厂，再补充同 MAIN 光标实际读回恢复和
模块释放，随后才允许图形及窗口清理。未清零的真实 Release 不冒充销毁。

## 桌面恢复实现与当前边界

`terminal_graphics_desktop.py` 已实现创建 D3D 设备前的显示器/模式/gamma/光标基线，
及模式恢复后再次比较 gamma、光标、任务栏、工作区和原前台寿命的流程。
每次写入前重新核对用户输入、显示器和 shell 身份；只恢复本轮可归因的差异，
最后要求两次稳定读回。无变化也必须实际核对，gamma 返回 TRUE 但读回不变会拒绝。
父进程不代替 MAIN 修补 ShowCursor 计数，不重启 Explorer，不屏蔽用户输入。

32项离线恢复回归通过；WindowsBackend 的原生准入仍明确关闭。恢复回执格式检查
不是来源认证，未来 runner 还必须从真实 wire/Job 记录独立认证每个释放阶段。
Python 时间检查不能打断驱动中阻塞的 Win32 调用，外部硬超时保护尚需接入。
本轮没有占用桌面，因此没有“实测桌面已恢复”的新结论。

## 证据和局限

图形 v6 模型64.656秒、4,493,961次原指令钩子、923个 API，连续到输入入口并完成
补充清理。输入完整模型在同一调用栈上继续执行原发布，具体计数、来源 SHA 和结果见
`analysis/terminal-graphics-platform-preflight-v1-20261114.json`。
旧 caps 只作为已标明的模型输入；模式、HRESULT、设备、字体尺寸/空白光栅、输入设备
和光标均为符号值。模型模块加载数也未等价模拟 Windows 模块引用，零账本不是真实释放。

模型的完整状态摘要、原字节核对、ABI 与篡改拒绝继续保留；但没有独立完整指令重放，
也没有两例全新原生寿命。补充清理使用独立 WORK_STACK，断言挂起的64KiB WinMain栈
不变，但只存摘要；清理后原挂起状态和 GAME 全局不可接续，不能称 WinMain 自然退出。

跨职责独立复核分别记录在 graphics/input independent-review 小报告中。大型模型与
最终构建只保留 F 盘 `.venv-audit`，Git 保存源码、必要小报告及校验清单。当前草稿、
被替代构建和中间 obj 的具体退役与容量见 closeout；原成功来源和游戏资产未改写。

## 下一关口和止损

下一单元先闭合以下实测准入，不追加截图、VM 或原机现场搬运：

1. 将父恢复流程接入有外部硬超时的宿主 runner，认证真实释放回执和资产 cwd。
2. 核对 D3D adapter 与桌面 gamma 显示器对应，补纹理解锁后重新只读 Lock 的持久字节
   读回；目前仅同一次 Lock 内读回，不能冒充解锁后的设备持久性。
3. 在离线准入通过后，提前告知并取得新的有界宿主窗口授权，单例验证实际 D3D/字体/
   输入创建、原发布及正常清理。当前没有启动许可，也不要求用户操作游戏。
4. 真实平台通过后，再在同一所有者中接入真实场景 worker、等待返回和首次结果消费。

单次完整模型上限90秒、600万指令、压缩8MiB；这是已定位原1MiB队列初始化后的
明确离线预算，不是扩大原生测试额度。当前单元仍遵守离线60分钟止损。
预检成功不勾选正式验收，不减少两例新寿命、完整状态/ABI/累计摘要、真实资源/PTD
释放、独立完整重放、篡改拒绝、严格规格及独立复核要求。
