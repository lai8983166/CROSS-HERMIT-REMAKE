# 原版双方普通近战

本单元对应R4的双方自动交战，change为`connect-original-bilateral-combat`。它接续[敌方追击](battle_enemy_pursuit.md)的完整世界执行器，既有执行器、模型与验收文件保持原字节。

## 输入与执行

同一声明资源/地图寿命中，两个使用槽的单位初始命令均为2，记录阵营分别4/0，彼此关系为1，目标/技能为−1。双方反应目标/技能亦明确为−1；双方HP/上限1000、攻击50、命中100、闪避0、防御10、精神1000、射程5；站在已验近距离位置，各使用当前案例的同一基础近战职业。输入是新的研究夹具，不是原场景加载器/存档恢复的证明。

先原467020绑定动画和437C90初始化双方各两份路径包；此后仅调用完整46B470，每帧检查250槽并自然执行两个46B760。无主机攻击/停止/坐标/HP根或派生状态写入。四职业案例要求每方至少两次命中，再保留一完整世界帧；双方不敌对、双方搜索禁用为96帧对照，另设玩家命令5的单方被动对照。

执行器以只读方式在真实函数入口和自然返回处保留双方完整记录/单位、队列、随机状态及身份。原48AD03判定结果与48AAE0参数关联，避免继承工具固定把UNIT称攻击者、TARGET称受害者的误解。双方HP store直接记录原PC、记录地址、宽度、值和世界帧。

反向出手揭示的12字节包身份字段是byte2=攻击者槽索引、byte3=目标槽索引；前两个字节不是攻击者ID。受伤记录+A6也从byte2取来源。单向索引0的旧样本不足以暴露这一区别，双向索引1案例会拒绝沿用旧推断。

当前输入保留玩家侦测范围0、攻击范围5。首次仍可通过全图搜索或实际受击记录选敌，但基础类型2在阶段24重新检查侦测掩码，失败后请求15并清除目标；不能因仍在攻击范围内就预测直接重入。47E460查询同阵营/友方支援范围，当前只有该玩家自身，没有其它友军；它不是额外“反击技能”。

## 验证范围

- 新实例要求所有拥有区域、逐帧/逐单位状态、57寄存器CPU、原指令/写入摘要、调用与观察证据精确一致；只有实际OS TLS槽/线程身份按原契约分别核对。
- 独立模型以明确的**函数入口检查点输入**核对待机/请求消化/目标绑定/选敌、双方物理快照/伤害/随机流、效果包到HP队列、整记录HP应用和自然恢复。每个HP从声明1000接续，全部HP store与每帧结果必须一致；所有原游戏/CRT随机函数连续核对。
- 这是局部函数契约的独立计算，加完整原实例重放；不是新增的完整世界逐字节独立预测模型。动画、分配器、全部AI分支等状态在本单元通过原代码执行和重放检查，其旧独立模型不能直接作双方完整证明。
- 原指令guard算法及call/base_call/API叶接口保持原实现，只在私有FunctionType中扩展按反汇编界定的完整原函数范围。47B800/47B920、492E20起记录清理、47CE70、47C210、47E460和43C1D0相关分支以实际到达情况报告。早期未知PC停止保留为未通过诊断，不计验收。旧夹具的玩家反应对象默认0会触发47B920并攻击单位0，导致搜索禁用对照仍出手；正式v3在首次原根前声明双方反应目标/技能−1，重新采集全部七例，旧v1/v2保持诊断身份。

## 边界

本单元无需交互桌面或解锁；不改Godot。它不完成死亡/胜败/奖励、技能/魔法/治疗/异常状态、完整反击系统、粗区域/复杂动态追击或原生外层线程/保留任务/渲染同寿命集成。R3/R4/R6保持进行中，目标2026-11-20不变。受攻击后自动重新锁敌不等于已验独立“反击技能”系统。
