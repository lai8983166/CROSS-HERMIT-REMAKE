# 原版启动、对象初始化及退出寿命（2026-10-20）

原版已在同一次真实执行中完成窗口后处理、COM、游戏工厂、字体/缓存、设备与管理器初始化并进入 WinMain 主循环；向实验窗口发送 WM_CLOSE 后，原代码执行游戏析构并清空游戏、主对象、字体缓存。两次独立运行均已退出整个自有进程树，没有强制终止。R1已通过[最终验收](../analysis/school-startup-lifetime-acceptance-20261020.json)，对应change任务3/3完成并归档；原连续VM的渲染连接仍属于R2。

## 执行方法和证据性质

[观察器](../tools/school_startup_lifetime.py)复用既有原进程读取工具，在具有kill-on-close约束的独立Job内正常启动未修改的原EXE及其保护层子进程。它只读原进程内存、短暂挂起线程采集实际WOW64上下文和栈，再恢复线程；关闭前再次核对窗口所属PID、Job成员和CPP_CLASS属性，唯一主动消息是发给本实验窗口的WM_CLOSE。已有同类窗口时拒绝实验，不操作用户窗口。

[原生记录v3](../analysis/school-startup-lifetime-native-v3-20261020.json)保留两次真实工厂调用、主循环、完整主对象/游戏对象/字体/缓存、COM接口、队列容量和缓冲区摘要、窗口归属、退出期间线程栈、进程树成员及退出码。[交叉核验](../analysis/school-startup-lifetime-verification-v1-20261020.json)来自独立读取原反汇编与记录的校验器；它没有复用观察器的取样代码。

这些是原程序正常执行的状态和调用栈采样，并非逐条原生指令或全部API返回日志。此前[窗口创建实验](school_startup_window.md)在客体中重放至4504E1；本批完整启动由真实原程序从头执行，不声称该客体已从4504E1连续重放全部音频/COM/游戏工厂，也不声称接回了原连续VM。原代码、IAT、通用寄存器均未写入或代换。

## 启动调用链及实际对象

两次工厂前采样均定位真实 `WinMain49DF85 →450570 →4135D0`，返回地址49DF8A、45060F及CRT调用者5714E6在同一线程栈上；此时7A49FC、80A398为0。随后同一PID、主对象与HWND进入WinMain主循环，游戏及字体缓存均非零。所涉及20段原函数的实时字节与来源映像逐段一致。

原导入目录明确确认：

| 原调用 | 实际接口/作用 |
| --- | --- |
| 4504FE、450513 | ShowWindow、UpdateWindow |
| 45052D、450547 | GetClientRect、GetWindowRect；不是ClientToScreen |
| 49DEF5 | CoInitialize；WinMain实际保存的HRESULT非负 |
| 49DF5B | InitCommonControlsEx；实际保存结果非零 |
| 45060A | 4135D0音频COM初始化；实际对象指向dmime/dmloader系统实现 |
| 45063A | 413630次级初始化；失败会警告后继续 |
| 45067A、4506AC | 413450设备/字体/队列，413560后处理 |
| 4506E9 | 成功后发布游戏输出；随后原WinMain进入循环 |

工厂成功是从来源控制流和实际发布/循环状态交叉推导的；不是捏造一条捕获到的EAX返回。音频和次级初始化允许警告后继续，因此游戏发布本身不能证明它们每个HRESULT成功；记录另行保留音频COM实际对象及映射模块。

对象关系已核对：

- 主对象大小1110h，原vtable5986A0，+4与全局7A0BB4及真实窗口一致；CPP_CLASS保存本次主对象。
- 游戏对象大小BA20h，B278/B27C为1024/768。实际启动走全屏分支，不能沿用独立窗口化实验对B204的假定。
- 管理器+1058为本次游戏对象，+105C为同一真实D3D8设备。两条队列容量为1000h项与100000h字节，实际分配的8000h/100000h字节均可读，分别保留完整摘要。
- B20C工厂与B210设备是本次实际COM对象，其虚函数指向SysWOW64/d3d8.dll；音频三项接口映射dmime.dll、dmloader.dll和dmime.dll。
- 1090/1094是两个678h字体对象，开头内嵌字体名；其+58设备、+5C纹理、+60顶点资源已建立。B270是80字节D3DX字体，指向实际共享缓存和同一设备。
- 80A398缓存176字节，含同一设备、32字节sprite、GDI DC/位图及256×256×4的实际像素缓冲。static字体的CreateFontIndirectA句柄与B26C原始CreateFontA句柄分别核对非零，不能错误要求它们相等。

## 原退出和错误分支

实际关闭路径与源指令一致：WM_CLOSE的450F6E调用DestroyWindow；WM_DESTROY的450F84调用PostQuitMessage；424A30经4248E0/424958移除CPP_CLASS。原GetMessage返回0后跳49E092，先结束任务，再经450730、412DD0释放游戏，删除主对象并清空7A49FC、7A4A00；字体缓存80A398也归零。记录实际捕获450797、412DF5、49E0DE在同一析构栈，以及最终全局归零后的WinMain尾部。窗口与属性的最终检查均为空。

正常游戏清理与保护层进程退出分别报告：父进程返回0，子进程返回C0000354（STATUS_DEBUGGER_INACTIVE）。微软[状态码说明](https://winprotocoldoc.z19.web.core.windows.net/MS-ERREF/%5BMS-ERREF%5D.pdf)将其定义为调试端口删除期间的操作失败。原版使用自调试保护层，重复启动的退出也出现同一状态，这支持保护层退出关联的推断；本批没有逐条逆向保护层最后的CRT/调试端口操作，不能把子进程状态冒充WinMain返回值或称全部进程退出码均为0。

核验器另外用实际采到的WinMain栈独立执行49E131–49E147原尾部，验证ret10、栈平衡和返回0。这是声明入口的原代码重放，不声称捕获了原生最后一条ret。取样若已进入CRT退出，观察器也能单独记录5714F2调用帧中的实际WinMain结果与exit参数；本批两组接受记录捕获的是WinMain清理尾部。

实际重复启动在另一自有Job中自然结束，原窗口保持。六个统一分支探针分别检查重复窗口、创建失败、COM失败、工厂失败、设备失败、后处理失败的原控制流。除了重复窗口值来自本次真实FindWindow外，失败输入均明确声明为隔离分支输入；探针停止在下一外部调用或清理函数入口，不代换API/游戏返回，不把系统从未发生的失败说成实际观测，也不声称穷举所有系统故障组合。

原代码没有显式注销类：窗口/属性沿原消息链清理，类注册最终随进程结束。不能把此前助手强制结束写成原版正常销毁，也不虚构UnregisterClassA调用。

相关回归42项通过。严格规格在归档前为32项、归档后为31项，减少的是已归档change的验证入口，未删除总规格。[保全记录](../analysis/school-startup-lifetime-preservation-20261020.json)核对16589个历史文件、10项存档规则及9个私有VM检查点。安装目录里的存档具有2026-10-02的修改时间、内容与下载原件不同；[额外完整启动比对](../analysis/school-startup-lifetime-save-recheck-20261020.json)分别核对两者，实际安装存档及占位文件在启动前后字节、长度和时间戳一致，下载原件也保持原哈希，没有用下载版本覆盖用户后来保存的版本。
