# 同一 MAIN 所有者中的原窗口回调接续

2026-11-13，本轮完成窗口准备与同步回调的代码接入和有界离线验证。没有启动任何
原生助手、游戏或窗口，没有截图、输入或桌面变化。正式任务仍为 **2/8**。

## 实际推进的边界

`terminal_window_preparation.py` 将原查重、RECT、图标、光标、画刷和类注册叶接到当前
MAIN 所有者；只适配原指针所指的缓冲区，不修改原类结构或 IAT。真实 HINSTANCE 必须
在 WinMain 开始前作为输入提供，不能在旧寿命的栈中补写一个新句柄。

`terminal_window_callbacks.py` 可在原 CreateWindowExA 尚未返回时处理真实 WNDPROC
通知，执行原 `424980`，递归处理 DefWindowProcA 引出的嵌套通知，返回原结果，再恢复
暂停的外层上下文。每层使用独立栈与带边界填充值的数据区，核对全部 57 项 CPU 状态。
仅在受声明的外部 API 停点页放置未执行的 `C3` 解码哨兵，避免 Unicorn 跨页预解码；
原代码、常量和 IAT 原字节不变。已知 lParam 数据使用显式影子映射，默认过程收到真实
原生指针，前后数据逐字核对；不丢弃客体对数据的写入而继续执行。

原生扩展保持旧 Reader、worker 与队列实现。回调仍在真实 MAIN TID/TEB 上运行，
释放 stateMutex 后进入可回调的 USER32 叶，在回调内部从同一 MAIN 队列取请求；
按请求、父回调、深度、HWND 和参数拒绝错配。每次入口采集实际 TLS 值和完整116字节
PTD，并保留 LastError。资源模块、窗口类和窗口纳入 STATUS 与 Shutdown 检查。
窗口开关默认关闭，源码/二进制的存在不构成桌面测试授权。

## 本轮验证及其限制

复用固定来源 `school-window-startup-trajectory-v3-20261020.json`，SHA-256
`a5f30898f2add507e70277617838ad51e5328b56915c227460e3bc43f2afcd48`。
两例分别从其保留的 `49DE2C` 状态出发，经原准备、注册、创建、回调返回和 HWND 发布，
连续到 `4504E1`：每例5273条原指令，其中300条外层准备/发布指令、4973条回调指令；
9个原准备叶，17次回调，最大嵌套深度3。全部原指令顺序、调用返回 ABI、原10项终点
CPU 和完整 MAIN 字节与来源一致；每次回调的57项外层 CPU 状态完整复原。临时缓冲区
模型全部释放，12项错误线程、TEB、父请求、深度、载荷等拒绝检查通过。

历史 HWND/HINSTANCE 等数值在本轮仅是离线输入，不作为当前有效句柄调用。旧来源没有
当前 TID/TEB/TLS，因此传输身份123/456、无TLS及临时缓冲区明确作为模型字段；实际
平台结果来自旧来源。该验证没有证明新的互斥锁重入、原生回调、原生资源释放或新的
完整状态来源。新原生助手已用 x86 `/W4 /WX` 编译，尚未执行。
