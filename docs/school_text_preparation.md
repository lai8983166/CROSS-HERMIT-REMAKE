# 首条文字准备与开场预览来源（2026-10-12）

三组真实学校编班 CPU 检查点完整重现七个已固定父阶段后，继续自然 `4C4DC0(0,script+676,0)`。它把面板4对应的层7设为文字目标，配置原点715/691及层指针，正常返回到 VM 根调用。下一次明确驱动的原版 VM 调用执行 opcode17：`4C2120` 根据文字表偏移查找索引0，`4CD5B0` 按双字节复制和分行，`4CABD0` 准备第一个文字记录。

首句 Big5 字节解码为「瑟希莉絲、伊里安。」只有一行。文字对象记录的七个16位值为2、0、24、0、12、0、22。第二个原始参数保留返回AX=12以外的寄存器高字；不得清理为纯整数12。

原版 `4CAD03` 通过导入槽5920A0调用 CreateFontA，CPU 自然停在E300000第一条指令之前，返回地址4CAD09。十四项栈参数及CP932字体名「ＭＳ ゴシック」原字节已记录，三个嵌套帧和根返回链均核对。没有返回虚假字体句柄，没有执行字体 API、文字排版或文字就绪，也未执行完整对白、波次、任务音频门控和世界调度。54个终端绘图接口只记录严格调用者/参数，未执行GPU。

独立工具解码原EXE关键指令与T0005文字表、指令顺序、双字节分行、记录字段及字体输入，比较八个完整内存区域、全部栈参数与绘图序列。其余119496650字节映射内存保持原值。两组拒绝继承不可变父证据；没有重跑全部更早上游。

`school_text_preparation_rules.json` 与 `school_text_preparation_evidence.json` 是分离的审计数据，不供运行时读取。运行时只使用单独的 `school_opening_dialogue.json`：从原脚本按指令顺序提取十段文字，保留繁体原文，模式为只读开场预览。这十段源文本的导出不表示原版已执行后续九段文字指令。Godot 展示不模拟原版字体指标、打字速度、发言者或演出，也不推进学校状态、存档、必修冒险门控或战斗。
