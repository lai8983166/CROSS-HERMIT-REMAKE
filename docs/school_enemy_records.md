# 场景单位模板到战术记录

本轮继续实际学校CPU的`453540`入口，读取场景5的原版模板指针表`6A7F6C`及数量表`6A85AC`。该场景有35条84字节模板，从单位索引249倒序安排到215；模板混有不同归属与状态，不能把它们都当作已出场敌人。

原版`4DA450`先经`4DA5F0`选择48字节人物概要，再由`4DFC20`计算176字节战术记录，调用`4E0A00`约束范围，最后覆盖场景模板的状态、类别、位置和模式字段。角色编号小于200时，从EXE原版人物定义表`6F5088`摘取职业、七属性、等级和武器类型，暂存在`7E11B0`的48字节区；编号大于等于200时，读取`72ED88+(编号-200)*48`的原始固定概要。这个转换路径不会应用持久装备/技能修正，不能用当前学生的另一条战术派生路径代替。

连续学校链路仅执行首条模板的记录转换，在首个场景单位`4680B0`入口之前停止；索引249、角色5、职业4、状态1、类别7、模板坐标52,65。此时单位工作仍全零，未建立它的动画资源或执行出场定位。三种就绪学校分支验证首条记录，两个拒绝分支不进入该入口；本轮新增阶段不会读取档案、分配资源、调用GPU/窗口/调度边界。

全部35条记录另用明确声明的驱动调用执行原版函数，人物数据取自原版EXE定义表；这不是实际学校敌人构造循环完成的见证。模板状态1有11条，状态0有24条；类别7有2条、类别0有1条、类别5有31条、类别6有1条。实际部署、待触发波次及事件含义需要后续`4680B0/468910`和`t0005` VM继续验证。模板中的状态、归属和坐标是输入，不能单凭它们宣称35个单位已进入战场。

写入白名单只包含当前选定176字节记录、人物分支的48字节概要临时区、栈及SEH。每次转换冻结所有其他已映射字节，执行后逐字节核对，包含当前队伍工作/记录、所有控制对象/元数据/纹理、地图/逻辑计数、效果、全局与持久数据。固定概要分支连临时区也须保持。清理是原版调用地址、目标和长度均精确的CRT边界；记录转换、数值和范围函数执行原始x86指令，没有替它们返回预制记录。

独立来源工具`tools/school_enemy_records_catalog.py`直接读EXE的场景模板、固定概要、职业与攻击原型行、等级ENGAGE表、移动类型表及五段原函数体。依据原指令公式重算完整记录，解码86组范围约束，再按原版顺序应用场景覆盖。窄字段先截断，再按各字段MOVSX或无符号读取进行约束；负回复值按有符号字段被限制为1，不可把所有16位字段当作无符号；类别7由场景覆盖发生在类别最大5的约束之后，必须保留7。新增记录与当前学生接口属于不同来源路径，角色5使用原始定义而非`7E17E8`持久成长目录。

规则与冻结原版fixture分别导出到`prototype/data/school_enemy_records_rules.json`和`prototype/data/school_enemy_records_evidence.json`，不作为已部署的Godot战斗世界。下一步继续首个场景单位构造及其余模板的资源/缓存和工作初始化，然后执行真实站位与VM/波次事件。

首次取证误用持久目录作为角色5输入快照，正常输入恰好相同；属性/职业反事实探针确认4DA5F0实际读取EXE定义表。修正取证地址和来源标注后重新运行连续学校，旧v1中止日志保留，正式证据用新v2路径。隔离诊断初次还误记范围函数返回地址为4E08B6，按反汇编校正为4E08C8后重跑，不替原函数返回。

正式连续学校报告`analysis/school-enemy-records-v2-20261010.json`的SHA256为`afe6d5f2e9076de16c294cf305342e8208aa29fa31c3abe1096c6f28ac4e3e21`。三种实际就绪/两种拒绝分支、四项原版专项通过；声明35条模板转换每次保留约103MB其他映射数据。
