# 返回流程演示

此演示复用已验收的返回事务，战果来自明确选择的场景5源输入；本地战斗胜负不生成原版条件世界或state11单位记录。完整范围见 `battle_return_audit.md` §63、66。

## 会话边界

`prototype/sim/campaign_return_demo.gd` 只保留经SHA核对的来源规则、初始目录和输入，排除expected_after等期望输出。阶段为battle→result→settled→school；实际终局建立战果，确认完成后置字段，进入学校才执行剧情/唯一完整周/已捕获学校数据。读取视图及重复确认不再发布，重开创建全新目录。

演示布阵使用原布阵前三名友方，赋予稳定ID3/4/9，并保留敌方；默认JSON不改写。来源异常或角色不匹配阻断到错误状态，允许重开；不会用错误终局产生奖励。

学校仍只支持读取已捕获字段；编班、排课、教师课程工作表、通用VM及原版存档未实现。所有原版见证/完整学校初始化/存档写入标记保持false。

## 操作

启动 `prototype/project.godot` 的主场景后，在顶部选择“场景5 · 源路线A/B”，点击“开始返回流程演示”。本地三学生战斗约330个逻辑帧后展示战果；可沿用1/2/3倍速与空格暂停。界面分别显示本地胜负与源战果，两个路线点数不同，不根据本地winner选择路线。

点击“确认战果”，再点击“进入学校”。学校页可选择四名学生，查看属性、成长池、待命顺序和班级列表；长详情可用鼠标滚轮滚动。“返回战果”只切页，不结算。“重开返回流程演示”采用下拉框当前路线开始独立新会话，“回到战斗原型”恢复默认八单位布阵。演示战斗期间R重开当前路线；结果/学校页拦截地图快捷键与点击，避免误重开或穿透。

初始角色字段来自声明的源实验世界，等级可能与成长池不一致；战果如实显示原版函数重算后的字段，因此样例中等级也可能降低。未加入可信姓名/物品名称映射，使用稳定ID显示。

## 验证入口

```bash
godot --headless --path prototype -s res://sim/tests/test_runner.gd
godot --headless --path prototype -s res://ui/tests/test_campaign_return_window.gd
```

第二条运行实际主场景，通过Viewport输入分派点击按钮、选择学生和滚动详情，并核对快捷键隔离和恢复默认布阵。图形模式可去掉`--headless`并传入 `-- --capture-dir=<已存在的绝对目录>`，保存五张1024×768截图及verification.json；输出目录应为新的验收目录，避免覆盖已归档证据。
